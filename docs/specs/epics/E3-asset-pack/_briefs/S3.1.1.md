# S3.1.1 — Port the guard library, adapters and tests

## Goal

Install the shared guard library and the per-agent hook scripts under
`$RNF_HOME/share/agentkit/`, at the paths the old tool used, and port the old
hook test suite so it passes against scripts installed by `agentkit apply`.
Registering the hooks with the agents is S3.1.2, which waits on commons 0.10.1.

## Settled

- **Share-dir artifacts (owner, 2026-11-20).** A machine-scope apply has one
  root, `$HOME`, with one transaction and one state file. Scripts under
  `$RNF_HOME/share/agentkit/` are therefore written as paths relative to
  `$HOME`, and `RNF_HOME` must be under `HOME`:

    - `adapters/spec.py` gains `class Base(StrEnum)`, with `ROOT = "root"` and
      `SHARE = "share"`, and `ArtifactSpec` gains a last field
      `base: Base = Base.ROOT`. A `SHARE` spec's `path` is relative to the
      target's work dir: `$RNF_HOME/share/agentkit` at machine scope, and
      `<repo>/.rn-forge/agentkit` at repo scope.
    - `adapters/__init__.py` gains `_destination(target, spec) -> str`. A `ROOT`
      spec returns `spec.path`. A `SHARE` spec returns
      `(target.work_dir.relative_to(target.root) / spec.path).as_posix()`.
    - When `target.work_dir.is_relative_to(target.root)` is false, `_destination`
      raises
      `AppException("{} is outside {}: agentkit installs its hook scripts there, so RNF_HOME must be under HOME", target.work_dir, target.root)`.
      The CLI maps it to exit 1.
    - `render`, `owned_paths` and `executable_paths` all use `_destination`.
      `owned_paths` and `executable_paths` therefore take `target: Target` in
      place of `scope: Scope`.
    - Update their two call sites in `operations.py`: `build_plan` (line 61) and
      `run_apply` (line 80).

- **The guard library belongs to no agent.** Both agents' scripts source
  `_common/hooks/guard-core.sh`. If one adapter declared it, `apply --agent`
  for the other agent would not install it, and if both did, the destinations
  would collide.

    - `adapters/__init__.py` gains
      `COMMON: dict[Scope, tuple[ArtifactSpec, ...]] = {Scope.MACHINE: hooks.COMMON}`.
    - `render` appends the `COMMON` specs for the target scope after the agents'
      specs whenever `agents` is non-empty, with the template context
      `{"agent": "_common", "scope": ..., "config": {}}`.
    - `owned_paths` never includes `COMMON` paths, so they are always planned, as
      S2.2's repository artifacts are. `executable_paths` includes the `COMMON`
      executables.

- **Specs in `src/rn_forge/agentkit/adapters/hooks.py`.** All are
  `ArtifactKind.MANAGED` with `base=Base.SHARE`:

    - `COMMON`: `_common/hooks/guard-core.sh`, from source
      `hooks/_common/guard-core.sh`, **not** executable. It is sourced, never
      run. The installed v0 copy is mode 0600.
    - `CLAUDE`: `claude/hooks/<name>.sh` from `hooks/claude/<name>.sh`, with
      `executable=True`, for each of `pre-bash-guard`, `pre-write-protect`,
      `session-compact-context` and `user-prompt-secret-guard`.
    - `CODEX`: `codex/hooks/<name>.sh` from `hooks/codex/<name>.sh`, with
      `executable=True`, for each of `pre-bash-guard`, `pre-write-protect` and
      `user-prompt-secret-guard`.

    All are copied verbatim (`template=False`). The scripts contain `${...}` and
    `{#`, which Jinja would misread. Do not edit `claude.py` or `codex.py`: they
    already splice `hooks.CLAUDE` and `hooks.CODEX` in. S2.1.1
    (`instructions.py`) and S3.2.1 (`skills.py`) run in parallel.

## Current behaviour

- `adapters/hooks.py` defines `CLAUDE = ()` and `CODEX = ()`. There is no
  `COMMON`, no `Base`, and no `assets/` directory.
- `adapters/__init__.py:61-68`: `owned_paths` and `executable_paths` take a
  `Scope`. `render` (`:39-58`) uses `spec.path` as the destination.
- The ported tests fail because no script exists at
  `<rnf>/share/agentkit/<agent>/hooks/<script>`: `subprocess.run` raises
  `FileNotFoundError` or `PermissionError` before the change.

## Tests first

`tests/hooks/test_install.py`, using `isolated_env`:

1. `test_s3_1_1_scripts_install_with_mode_0755`: after `apply`, each of the
   seven agent scripts under `<rnf>/share/agentkit/{claude,codex}/hooks/` has
   `stat.S_IMODE(...) == 0o755`, and `_common/hooks/guard-core.sh` exists.
1. `test_s3_1_1_agent_filter_installs_common_library`: after
   `apply --agent codex`, the guard library and the three codex scripts exist,
   and no `claude/hooks/` script does.
1. `test_s3_1_1_rnf_home_outside_home_fails`: set `RNF_HOME` to
   `tmp_path / "elsewhere"`, which is outside `HOME`. Then `apply` returns 1,
   the captured output contains `RNF_HOME must be under HOME`, and
   `tmp_path / "elsewhere" / "share" / "agentkit" / "state.json"` does not
   exist.
1. `test_s3_1_1_scripts_say_agentkit_apply`: no installed script contains
   `agentkit global apply`, and each `pre-*` and `user-prompt-*` script
   contains `Re-run agentkit apply.`.

Then the ported suite, `tests/hooks/test_guard_scripts.py`. It covers both
dialects (Claude exits 2 with the reason on stderr; Codex prints
`{"decision":"block"}` and exits 0) and malformed input
(`test_s3_1_1_command_guard_fails_closed_on_unusable_events`,
`test_s3_1_1_write_guard_fails_closed_on_unusable_events`,
`test_s3_1_1_prompt_guard_warns_rather_than_blocking_on_bad_events`). Each test
fails before the change, because no script is installed.
