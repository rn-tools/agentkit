# S3.1.2 — Register the hooks for both agents

Brief for
[S3.1.2](../F3.1-guard-hooks.md#s312-register-the-hooks-for-both-agents), at the
commit that adds this brief (parent `95f9445`).

## Goal

Register the installed guard scripts with both agents: the owned `hooks` key in
`~/.claude/settings.json`, and a managed `~/.codex/hooks.json`. Command paths
render from `RNF_HOME` at apply time. With `RNF_HOME` unset, they render as the
literal `$HOME/.rn-forge/share/agentkit/...`, so the Codex file is
byte-identical to today's live file and Codex's hook trust holds.

## Settled

- **The share prefix.** `src/rn_forge/agentkit/adapters/hooks.py` gains
  `share_prefix() -> str`. It reads `os.environ.get("RNF_HOME")`. When that is
  unset or empty, it returns the literal `"$HOME/.rn-forge/share/agentkit"`.
  Otherwise it returns
  `(Path(value).expanduser() / "share" / "agentkit").as_posix()`. This mirrors
  tooling's `rnf_home()` ("unset or empty" means the default).

- **Template context.** Both context dicts in `adapters.render` (the per-agent
  one and the `COMMON` one) gain `"share": hooks.share_prefix()`.

- **A keys spec may take values from a rendered document.** In `_emit`'s `KEYS`
  branch, when `spec.source` is non-empty:

    - Render the source as the other branch does: through `TemplateEngine` when
      `spec.template`, else read it verbatim. Parse the result with `json.loads`
      into `document`.
    - For each key path, take the value from `document` when
      `DictUtils.get(document, path, default=_ABSENT)` finds one, else from the
      config as now.
    - With `source == ""` behaviour is unchanged.

    Document this in `ArtifactSpec`'s docstring under `keys` and `source`.

- **Claude.** In `adapters/settings.py`, the Claude spec gains
  `source="hooks/claude/settings-hooks.json.j2"` and `template=True`, and
  `"hooks"` joins its `keys`, kept alphabetical. The new asset
  `src/rn_forge/agentkit/assets/hooks/claude/settings-hooks.json.j2` is
  `{"hooks": ...}`, holding the v0 `hooks` value from
  `/Users/rohitnarayanan/Devel/workspaces/rn_backup/agentkit/src/rn_forge/agentkit/agents/claude/defaults/global.json`
  (read-only). Each `$HOME/.rn-forge/share/agentkit` prefix becomes
  `{{ share }}`. That gives four registrations: `UserPromptSubmit`;
  `PreToolUse` with matchers `Bash` and `Write|Edit|MultiEdit|NotebookEdit`;
  and `SessionStart` with matcher `compact`. Each has its v0 `statusMessage`.

- **Codex.** `hooks.CODEX` gains, after the scripts,
  `ArtifactSpec(".codex/hooks.json", ArtifactKind.MANAGED, "hooks/codex/hooks.json.j2", template=True)`.
  This is `Base.ROOT`, not executable. The asset
  `src/rn_forge/agentkit/assets/hooks/codex/hooks.json.j2` is the committed
  snapshot `tests/snapshots/hooks/codex-hooks.json` (the live 2026-11-14 file,
  865 bytes, trailing newline), with each `$HOME/.rn-forge/share/agentkit`
  replaced by `{{ share }}` and nothing else changed. Commons `TemplateEngine`
  keeps the trailing newline.

- **`assets/**` is excluded from mdformat** (`.mdformat.toml`), and `.j2` is not
  TOML, YAML or Python, so `task format` leaves the templates alone.

## Current behaviour

- `hooks.CODEX` lists the three scripts only, and no spec names
  `.codex/hooks.json`. After `apply` in a temp `HOME`, that file does not
  exist.
- The Claude settings spec's `keys` lack `hooks`, and
  `test_s1_4_2_claude_owned_keys_only` asserts `"hooks" not in actual`.
- No template context has `share`.
- So the new tests fail with `FileNotFoundError` on `.codex/hooks.json`, or
  `KeyError: 'hooks'` on the parsed `settings.json`.
