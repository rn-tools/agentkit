# S3.2.1 — Package and install the two skills

Brief for [S3.2.1](../F3.2-skills.md#s321-package-and-install-the-two-skills),
at the commit that adds this brief (parent `de02075`).

## Goal

Package `dev-team-orchestration` and `sonar-cleanup`, copied from the live
`~/.claude/skills/`, and install them as managed files at machine scope to
`~/.claude/skills/<name>/SKILL.md` and `~/.codex/skills/<name>/SKILL.md`. The
user overlay can disable a skill per agent, and a disabled skill that was
installed is removed on the next apply.

## Settled

- **Codex gets identical copies (owner, 2026-11-20).** Neither live `SKILL.md`
  has `allowed-tools`. Both have front matter of `name` and `description`
  only, which is valid for Codex as it stands. So both agents get the same
  verbatim source, with no template. F3.2's "template conditional on agent
  name" has nothing to switch on while that holds. Record this on the story
  when it closes. The `ToolSearch` sentences in `sonar-cleanup` stay in the
  Codex copy.

- **Assets** are copied byte for byte with `cp`:

    - `~/.claude/skills/dev-team-orchestration/SKILL.md` →
      `src/rn_forge/agentkit/assets/skills/dev-team-orchestration/SKILL.md`
    - `~/.claude/skills/sonar-cleanup/SKILL.md` →
      `src/rn_forge/agentkit/assets/skills/sonar-cleanup/SKILL.md`

    Each directory holds only `SKILL.md`. Do not copy `.DS_Store` or
    `~/.claude/skills/synced/`. `.mdformat.toml` excludes
    `src/rn_forge/agentkit/assets/**` and `tests/snapshots/**` (reviewer,
    2026-11-20), so `task format` keeps the live bytes. Do not edit it.

- **Specs in `src/rn_forge/agentkit/adapters/skills.py`.**
  `SKILLS = ("dev-team-orchestration", "sonar-cleanup")`.

    - `CLAUDE` has, per name,
      `ArtifactSpec(f".claude/skills/{name}/SKILL.md", ArtifactKind.MANAGED, f"skills/{name}/SKILL.md", skill=name)`.
    - `CODEX` is the same with `.codex/skills/`.
    - Do not edit `claude.py` or `codex.py`: they already splice `skills.CLAUDE`
      and `skills.CODEX` in. S2.1.1 (`instructions.py`) and S3.1.1 (`hooks.py`,
      plus a `base` field and destination changes in `spec.py` and
      `__init__.py`) run in parallel. Keep your edits to `spec.py` and
      `__init__.py` to what is settled here.

- **Disabling, in the seam:**

    - `ArtifactSpec` (`adapters/spec.py:17`) gains a last field
      `skill: str | None = None`.
    - In `adapters.render` (`adapters/__init__.py:39`), per agent,
      `disabled = sources.config.get(agent.value, {}).get("skills", {}).get("disabled", [])`.
      A spec whose `skill` is in `disabled` is not rendered.
    - `owned_paths` still declares the spec's path, so its state entry is planned
      as stale. A clean file plans `delete`; a hand-edited one plans drift. That
      is commons' existing behaviour, and needs no code.
    - When `disabled` is not a list of strings, `render` raises
      `SourceError("[{}] skills.disabled: expected a list of skill names, got {!r}", agent.value, disabled)`,
      with `SourceError` from `rn_forge.agentkit.sources`.
    - The overlay spelling is `[codex]` then
      `skills.disabled = ["sonar-cleanup"]`, a dotted key that TOML reads as
      `{"skills": {"disabled": [...]}}`.

- **Snapshots:** `tests/snapshots/skills/<name>/SKILL.md` for both skills,
  copied with `cp` from the live files. Verify each with `cmp` against both
  the live file and the asset, and record the results in `## Result`.

## Current behaviour

- `adapters/skills.py` defines `CLAUDE = ()` and `CODEX = ()`. There is no
  `assets/` directory, and `ArtifactSpec` has no `skill` field.
- `adapters.render` renders every spec of each selected agent
  (`__init__.py:50`).
- `tests/test_skills.py` fails: it cannot construct a spec with `skill=`
  (`TypeError`), and nothing is installed.

## Tests first

`tests/test_skills.py`. It uses a `home` fixture as in `tests/test_adapters.py`
(`HOME` and `RNF_HOME` under `tmp_path`, no monkeypatching of `adapters`), and a
helper `overlay(home, text)` that writes
`<home>/.rn-forge/share/agentkit/config.toml`. `SNAP` is
`Path(__file__).parent / "snapshots" / "skills"`.

1. `test_s3_2_1_claude_copies_match_snapshots`: after `run(app, ["apply"])`,
   `<home>/.claude/skills/<name>/SKILL.md` has the same bytes as
   `SNAP / name / "SKILL.md"`, for both names.
1. `test_s3_2_1_codex_copies_have_codex_front_matter`: after `apply`, each
   `<home>/.codex/skills/<name>/SKILL.md`:
    - starts with `"---\n"`;
    - has front matter (the text between the first two `---` lines) whose keys
      are exactly `name` and `description`, split on the first `:` per line;
    - has `name: <name>`;
    - does not contain `allowed-tools`;
    - and equals the Claude copy.
1. `test_s3_2_1_disabled_skill_is_removed_on_apply`: `apply`, then
   `overlay(home, '[codex]\nskills.disabled = ["sonar-cleanup"]\n')`, then
   `apply` again. `.codex/skills/sonar-cleanup/SKILL.md` is gone,
   `.codex/skills/dev-team-orchestration/SKILL.md` and
   `.claude/skills/sonar-cleanup/SKILL.md` remain, and the state holds no
   `.codex/skills/sonar-cleanup/SKILL.md` entry.
1. `test_s3_2_1_disabled_must_be_a_list`:
   `overlay(home, '[codex]\nskills.disabled = "sonar-cleanup"\n')`. `apply`
   returns 1, and the captured output names `skills.disabled`.
