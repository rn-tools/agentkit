# S2.3.1 — Import and duplicate-heading checks

Brief for
[S2.3.1](../F2.3-instruction-doctor-checks.md#s231-import-and-duplicate-heading-checks),
at the commit that adds this brief (parent `6e06bb5`).

## Goal

Three warning findings that keep an instruction file's body and agentkit's block
from repeating each other, and keep `AGENTS.md` canonical. They join the
existing scope findings, so `plan` prints them for either scope and the
lifecycle `doctor` prints the machine scope's.

## Settled

- **Where.** A new module `src/rn_forge/agentkit/instruction_checks.py` with one
  public function, `instruction_findings(target: Target) -> list[Finding]`.
  `findings.scope_findings` calls it last and extends `found` with the result.
  Nothing else in `findings.py` changes.

- **Files checked**, as paths relative to `target.root`. A file that does not
  exist is skipped.

    - Machine scope: `.claude/CLAUDE.md` and `.codex/AGENTS.md`.
    - Repo scope: `AGENTS.md` and `CLAUDE.md`.

    The agent selection does not narrow this list.

- **The agentkit block** is `adapters.instructions.BLOCK`
  (`ManagedBlock("rn-forge agentkit", comment="<!--")`). Its text is
  `BLOCK.extract(text)`, and the body is `BLOCK.remove(text)`. A malformed
  marker raises `AppException` from commons; let it propagate.

- **Headings.** A heading is a line matching `^#{1,6}\s+(.+?)\s*#*\s*$` that is
  not inside a fenced code block (a line starting with three backticks or
  three tildes toggles the fence). Its text is the stripped group 1, compared
  exactly.

- **The three findings**, all `Severity.WARNING`. `<path>` is the path relative
  to `target.root`, as listed above:

    1. `agentkit.claude-import-missing`, repo scope only: `CLAUDE.md` exists and
       no line of it, stripped, equals `@AGENTS.md`. Message:
       `f"{path} does not import @AGENTS.md"`.
    1. `agentkit.heading-duplicated`, both scopes: for each file with an agentkit
       block, one finding per distinct heading text found both in the block and
       in the body, in block order. Message:
       `f"{path}: heading {text!r} is in both the body and agentkit's block"`.
    1. `agentkit.agents-points-at-claude`, both scopes: an `AGENTS.md` file
       (`.codex/AGENTS.md` or `AGENTS.md`) whose text contains
       `` Read `CLAUDE.md` now ``. Message:
       `f"{path} points at CLAUDE.md as canonical; AGENTS.md is canonical"`.

    Order in the result: per file in the order listed above, findings 1, 2, then
    3\.

## Current behaviour

- `findings.scope_findings` (`src/rn_forge/agentkit/findings.py:68-89`) reports
  missing programs (machine scope), vanished state files and invalid overlays
  only. No module reads instruction files.
- So each new test's `plan --json` findings list lacks the expected code, and
  the test fails on that assertion. Importing
  `rn_forge.agentkit.instruction_checks` fails with `ModuleNotFoundError`
  before the module exists, so write the tests against `plan` and `doctor`,
  not the module.

## Change

- **Change:** new `src/rn_forge/agentkit/instruction_checks.py`; one call added
  in `findings.scope_findings`; new `tests/test_instruction_checks.py`.
- **Leave alone:** every other module and test, `pyproject.toml`, `uv.lock`,
  every kiln-generated file, and every doc page except this brief's
  `## Result`.

## Tests first

`tests/test_instruction_checks.py`. Reuse the fixture patterns of
`tests/test_plan.py`: a temp `HOME` with `RNF_HOME` under it, the `which` stub
so no program-missing finding appears, and `adapters.render` monkeypatched to
return `[]` so `plan` writes nothing of its own. For repo scope, `git init` a
temp repo and pass `--scope repo --repo <path>`. Read findings from
`json.loads(capsys.readouterr().out)["findings"]`, keeping those whose `code`
starts with `agentkit.claude-import`, `agentkit.heading` or `agentkit.agents-`.
Every case returns `ExitCode.OK`: the findings are warnings.

1. `test_s2_3_1_claude_md_without_import_warns`: repo `CLAUDE.md` is
   `"# Claude\n\nNotes.\n"`. One `agentkit.claude-import-missing` whose
   message contains `CLAUDE.md`.
1. `test_s2_3_1_claude_md_with_import_is_clean`: repo `CLAUDE.md` is
   `"@AGENTS.md\n\n## Claude-only\n"`. No filtered findings.
1. `test_s2_3_1_no_import_check_at_machine_scope`: `<home>/.claude/CLAUDE.md`
   without `@AGENTS.md`; machine-scope `plan` gives no
   `agentkit.claude-import-missing`.
1. `test_s2_3_1_duplicate_heading_warns_both_scopes`: parametrised over
   (machine, `.claude/CLAUDE.md`), (machine, `.codex/AGENTS.md`) and (repo,
   `AGENTS.md`). The file holds a body with `## Safety` and `## Mine`, then an
   agentkit block (markers as `BLOCK.render("", "## Safety\n\n- x\n")` writes
   them) containing `## Safety`. Exactly one `agentkit.heading-duplicated`,
   whose message contains `'Safety'` and the path.
1. `test_s2_3_1_heading_in_code_fence_is_ignored`: as above, but the body's
   `## Safety` sits inside a fenced code block. No finding.
1. `test_s2_3_1_kiln_block_heading_counts_as_body`: repo `AGENTS.md` with a kiln
   block (`ManagedBlock("rn-forge kiln", comment="<!--")`) holding
   `## Agent workflow`, and an agentkit block holding `## Agent workflow`. One
   `agentkit.heading-duplicated`.
1. `test_s2_3_1_agents_pointer_warns`: repo `AGENTS.md` containing
   `` **Read `CLAUDE.md` now and follow it.** ``. One
   `agentkit.agents-points-at-claude`. The same text in
   `<home>/.codex/AGENTS.md` gives one at machine scope.
1. `test_s2_3_1_doctor_reports_machine_findings`: with the duplicate-heading
   `.claude/CLAUDE.md` of test 4, the lifecycle `doctor` (as
   `test_s1_3_2_doctor_runs_machine_findings` in `tests/test_plan.py` calls
   it) reports `agentkit.heading-duplicated`.

Each fails before the change because the findings list lacks the code.

## Out of scope

- Fixing or trimming any file; these are warnings only.
- Checks on any other file, or on headings across files.
- Changing an existing finding.
