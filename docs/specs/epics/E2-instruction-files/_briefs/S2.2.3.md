# S2.2.3 — gitignore block for derived files

Brief for
[S2.2.3](../F2.2-repository-block.md#s223-gitignore-block-for-derived-files), at
`7d916f8` plus S2.2.1 and S2.2.2.

## Goal

At repo scope, `apply` keeps a `# BEGIN rn-forge agentkit` block in
`<repo>/.gitignore`, so that the derived files under `.rn-forge/agentkit/` are
never committed. The committed `state.json` and `config.toml` stay tracked.

## Settled

- **Where:** `src/rn_forge/agentkit/repository.py`. At repo scope, `render`
  always returns
  `Artifact(".gitignore", ArtifactKind.BLOCK, GITIGNORE_BODY, GITIGNORE_BLOCK)`
  last, after the optional `AGENTS.md` block and the `CLAUDE.md` seed.

- `GITIGNORE_BLOCK = ManagedBlock("rn-forge agentkit")`, which uses the hash
  comment style. Its markers are `# BEGIN rn-forge agentkit` and
  `# END rn-forge agentkit`.

- `GITIGNORE_BODY` has exactly three lines:

    ```text
    .rn-forge/agentkit/backups/
    .rn-forge/agentkit/.staging/
    .rn-forge/agentkit/state.lock
    ```

    Each line ends with `\n`. `state.lock` goes beyond the story's acceptance
    (reviewer, 2026-11-20). Commons `StateStore.locked` writes `state.lock`
    beside `state.json` (commons `fs/state.py:190`), and kiln ignores its own
    `.rn-forge/kiln/state.lock` the same way. Record this line in the story's
    acceptance when it closes.

- **Placement is commons'.** An absent `.gitignore` is created holding only the
  block, with no leading blank line. A present one gets the block appended
  after one blank line, and every byte outside the block is kept
  (`ManagedBlock.render`, commons `fs/blocks.py:183`).

## Current behaviour

- After S2.2.2, `repository.render` returns the optional `AGENTS.md` block and
  the `CLAUDE.md` seed. Nothing touches `.gitignore`.
- `tests/test_gitignore.py` fails on its first assertion: `.gitignore` does not
  exist after `apply`.

## Tests first

`tests/test_gitignore.py`, with the same `home` and `repo` fixtures as
`tests/test_repo_block.py`, copied. Use:

```python
BLOCK = (
    "# BEGIN rn-forge agentkit\n"
    ".rn-forge/agentkit/backups/\n"
    ".rn-forge/agentkit/.staging/\n"
    ".rn-forge/agentkit/state.lock\n"
    "# END rn-forge agentkit\n"
)
KILN_GITIGNORE = (
    ".venv\n\n# BEGIN rn-forge kiln\n.rn-forge/kiln/backups/\n"
    ".rn-forge/kiln/state.lock\n# END rn-forge kiln\n"
)
```

1. `test_s2_2_3_absent_gitignore_is_created_with_the_block`: `apply`, then
   `(repo / ".gitignore").read_text() == BLOCK`.
1. `test_s2_2_3_kiln_block_is_byte_identical`: write `.gitignore` as
   `KILN_GITIGNORE`, then `apply`. It reads exactly
   `KILN_GITIGNORE + "\n" + BLOCK`, and
   `ManagedBlock("rn-forge kiln").extract(...)` is the same before and after. A
   second `--json apply` reports `.gitignore` as `unchanged`.
1. `test_s2_2_3_derived_files_ignored_state_tracked`: `apply`. Then create each
   path below that does not exist yet, as an empty file with its parent
   directories, so the check does not depend on how git matches absent paths.
   Then run `subprocess.run(["git", "check-ignore", "-q", <path>], cwd=repo)`
   for each path:
    - `.rn-forge/agentkit/backups/x` returns 0.
    - `.rn-forge/agentkit/.staging/x` returns 0.
    - `.rn-forge/agentkit/state.lock` returns 0.
    - `.rn-forge/agentkit/state.json` returns 1.
    - `.rn-forge/agentkit/config.toml` returns 1.
