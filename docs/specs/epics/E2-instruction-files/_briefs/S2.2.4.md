# S2.2.4 — Block survives the repository's Markdown formatter

Brief for
[S2.2.4](../F2.2-repository-block.md#s224-block-survives-the-repositorys-markdown-formatter),
at the commit that adds this brief (parent `7867825`).

## Goal

Make the body `repository.agents_block` builds exactly what mdformat at
`wrap = 80` would write, so that `task lint` passes on an applied `AGENTS.md`
and `task format` never turns the block into drift.

## Settled

- **Shape.** `agents_block` returns `""` when nothing is set, as now. Otherwise
  it returns `"\n## Agent workflow\n\n" + "\n".join(bullets) + "\n\n"`. The
  leading `"\n"` gives the blank line after the BEGIN marker, and the trailing
  `"\n\n"` the blank line before the END marker. Commons `ManagedBlock.render`
  writes the body's lines between the markers as given.

- **Wrapping.** Each bullet is the text it is today (`"- Worktrees: ..."`, and
  so on), wrapped greedily at 80 columns. Continuation lines are indented two
  spaces. A line may run past 80 only when a single token is longer than the
  room left. Tokens are matched by `` re.compile(r"(?:`[^`]*`|[^\s`])+") ``,
  so an inline code span (which may contain spaces) is never split, and
  punctuation stays attached. Tokens are joined by single spaces, which also
  collapses whitespace in `story_workflow` as `' '.join(...split())` does
  today. Put this in a private `_wrap(text: str) -> str` in `repository.py`,
  with `WRAP = 80` as a module constant.

- **Wrap width is fixed at 80.** This is kiln's mdformat default and this repo's
  `.mdformat.toml`. Reading a repo's own setting is not in scope.

## Current behaviour

- `agents_block` (`src/rn_forge/agentkit/repository.py:47-65`) returns
  `"## Agent workflow\n\n" + "\n".join(lines) + "\n"`, with no blank line
  after the BEGIN marker or before END, and no wrapping. The shared-checkout
  bullet is 104 characters.
- Observed on this repo (2026-11-21): after `apply --scope repo`, `task lint`
  fails with `Error: File ".../AGENTS.md" is not formatted.`. After
  `task format`, `plan --scope repo` shows `drift block AGENTS.md`.
- So the new tests fail: the round-trip test because `mdformat.text(...)`
  differs from the input, the formatted-plan test with `drift`, and the
  exact-body tests on the missing blank lines.

## Tests first

In `tests/test_repo_block.py`. `mdformat` is in the `docs` group, which
`task setup` installs; start each test that imports it with
`mdformat = pytest.importorskip("mdformat")`.

1. `test_s2_2_4_body_has_blank_lines_and_wraps`: `agents_block` for the
   `ALL_KEYS` table starts with `"\n## Agent workflow\n\n"` and ends with
   `"\n\n"`. Every line is at most 80 characters. The shared-checkout bullet
   is two lines, the second starting with two spaces.
1. `test_s2_2_4_block_is_mdformat_stable`: for each of `ALL_KEYS`, and a table
   whose `story_workflow` is about 300 characters and contains an inline code
   span with spaces placed across the 80-column boundary, the applied
   `AGENTS.md` text `t` (kiln fixture plus block) satisfies
   `mdformat.text(t, options={"wrap": 80}) == t`.
1. `test_s2_2_4_formatted_file_plans_unchanged`: apply with `ALL_KEYS`, rewrite
   `AGENTS.md` with `mdformat.text(..., options={"wrap": 80})`, then the
   `--json plan --scope repo` row for `AGENTS.md` is `unchanged`.
1. `test_s2_2_4_code_span_is_not_split`: `_wrap` on a bullet whose code span
   would straddle column 80 keeps the whole span on one line.

Each fails before the change as **Current behaviour** says (test 4 with
`ImportError` on `_wrap`).
