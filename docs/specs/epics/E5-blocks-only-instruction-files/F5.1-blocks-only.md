The repository `CLAUDE.md` seed becomes an agentkit block. `doctor` drops the
three checks that read body text.

## S5.1.1 — `CLAUDE.md` import as a block

**State:** Closed (2026-11-22)

**Acceptance:**

- At repository scope, `CLAUDE.md` is a BLOCK artifact named `rn-forge agentkit`
  whose content is the single line `@AGENTS.md`. The SEEDED `CLAUDE.md`
  artifact and `CLAUDE_SEED` are removed from `repository.py`.
- In a repository with no `CLAUDE.md`, `apply` creates it with only the block.
- In a repository whose `CLAUDE.md` has a body, `apply` inserts the block and
  leaves every byte of the body unchanged. This includes a body that already
  holds `@AGENTS.md`.
- `plan` for an existing repository shows `insert block CLAUDE.md`, with no
  conflict.
- The block is written even when the overlay sets no `[repo]` keys, because the
  import does not depend on them. The `AGENTS.md` block keeps its rule that an
  empty render is not written.
- Tests in `tests/test_repository.py` cover the absent file, the file with a
  body, and the file whose body already holds the import.

## S5.1.2 — `doctor` reads only agentkit's blocks

**State:** Closed (2026-11-22)

**Acceptance:**

- `doctor` no longer emits `agentkit.claude-import-missing`,
  `agentkit.heading-duplicated` or `agentkit.agents-points-at-claude`. The
  logic moves to [S5.2.1](F5.2-review-command.md#s521-agentkit-review), not
  deleted.
- `doctor` still reports malformed agentkit markers in an instruction file as an
  error. A missing block or an edit inside the block shows up as drift through
  the engine, as today.
- An edit anywhere in a body, or anywhere in kiln's block, produces no `doctor`
  finding. A test edits each region and asserts that doctor is silent.
- Tests in `tests/test_instruction_checks.py` that assert the three warnings
  move with the logic to the review command's tests.
- Malformed markers are the error finding `agentkit.block-malformed`; the three
  checks live in `review.py` as `review_findings`, called by no command yet.
