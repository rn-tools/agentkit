# S5.1.2 — `doctor` reads only agentkit's blocks

Brief for
[S5.1.2](../F5.1-blocks-only.md#s512-doctor-reads-only-agentkits-blocks), at
`9100c11`.

## Goal

`doctor`, and `plan`'s findings, stop reading the owner's body text in
instruction files. The only instruction-file check left in them is malformed
agentkit markers, now reported as an error finding. The three body checks move,
unchanged, into a new module `review.py`, which S5.2.1 turns into the
`agentkit review` command.

## Settled

- **New module `src/rn_forge/agentkit/review.py`.** Move the body of
  `src/rn_forge/agentkit/instruction_checks.py` into it as it stands at
  `9100c11`: `_PATHS`, `_HEADING`, `_headings` and `_duplicate_headings`, and
  the function renamed from `instruction_findings` to
  `review_findings(target: Target) -> list[Finding]`. Keep the three codes,
  severities and messages byte for byte. S5.2.1 renames them. The module
  docstring is
  `"""Advisory checks that read a whole instruction file, body included."""`. No
  command and no other module calls `review_findings` in this story.
- **`instruction_checks.py` keeps only the markers check.** Its docstring is
  `"""The instruction-file check doctor runs: malformed agentkit markers."""`.
  It imports `_PATHS` from `review.py`, so the path table exists once.
  `instruction_findings(target)` keeps its name and signature. For each path
  in `_PATHS[target.scope]` that exists, read it as UTF-8 and call
  `BLOCK.extract(text)`. On `AppException` (from
  `rn_forge.commons.exceptions`), append
  `Finding("agentkit.block-malformed", Severity.ERROR, f"{path}: {error.message}")`.
  A missing file is skipped. The function no longer raises, so drop its
  `Raises:` section.
- `findings.py` keeps calling `instruction_findings(target)` exactly as today.
  It needs no edit.
- A missing block, or an edit inside agentkit's block, is drift that the engine
  already reports through `plan`/`apply`. Add nothing for it.
- **Tests.** Move every test in `tests/test_instruction_checks.py` to a new
  `tests/test_review.py`, keeping each case and its expected code and message.
  They call `review_findings(resolve_target(...))` directly instead of running
  `plan`. Build the target the way `tests/test_repo_block.py` does with
  `resolve_target`. The moved tests keep their `test_s2_3_1_` names.
  `test_s2_3_1_doctor_reports_machine_findings` becomes
  `test_s2_3_1_review_reports_machine_findings`, which calls `review_findings`
  for the machine scope. After the move, `tests/test_instruction_checks.py`
  holds only the new S5.1.2 tests below.

## Current behaviour

At `9100c11`, `instruction_findings` emits the three body warnings, and it
raises `AppException` from `BLOCK.extract` on malformed markers, so `plan` fails
with an application error and not a finding. Against that code:

- The malformed-markers test fails. `plan` exits with the app-error code, and no
  `agentkit.block-malformed` finding is printed.
- The silent-doctor tests fail. A duplicated heading in the body yields
  `agentkit.heading-duplicated`, and a `CLAUDE.md` with no import yields
  `agentkit.claude-import-missing`.
- `tests/test_review.py` fails to import, because `review.py` does not exist.

## Tests first

Write the new tests in `tests/test_instruction_checks.py`, reusing its current
`home`, `repo`, `_write` and plan-running helpers. The helper that filters
findings must now keep every code that starts with `agentkit.` and is not about
programs on `PATH`. The `home` fixture already stubs `shutil.which` and
`adapters.render`, so the only findings left are instruction-file findings.

1. `test_s5_1_2_malformed_markers_are_an_error` (parametrized: repo `AGENTS.md`,
   machine `.claude/CLAUDE.md`): the file holds
   `"<!-- BEGIN rn-forge agentkit -->\nx\n"`, a begin marker with no end.
   `--json plan` exits with a non-OK code. Its JSON output has exactly one
   finding, with code `agentkit.block-malformed`, severity `error`, and a
   message that starts with `f"{path}: "`. Read `plan` in `commands.py`: it
   emits the JSON and then raises on error findings, so the output is printed
   before the exit.
1. `test_s5_1_2_body_edits_are_silent` (parametrized over regions): a repo
   `AGENTS.md` and `CLAUDE.md`, plus a machine `.claude/CLAUDE.md`, each hold
   text that would trip a body check at `9100c11`:
    - a body heading that duplicates one in agentkit's block
    - a kiln block (`ManagedBlock("rn-forge kiln", comment="<!--")`) whose
      heading duplicates one in agentkit's block
    - a `CLAUDE.md` with no `@AGENTS.md`
    - an `AGENTS.md` body with "Read `CLAUDE.md` now" For each case, `plan` exits
      OK with no instruction-file finding.
1. `test_s5_1_2_doctor_is_silent_on_body_edit`: a machine `.claude/CLAUDE.md`
   whose body duplicates a block heading. Running `doctor(PRODUCT, home=...)`,
   as the current `test_s2_3_1_doctor_reports_machine_findings` does, returns
   no finding with a code that starts with `agentkit.heading` or
   `agentkit.block`.
