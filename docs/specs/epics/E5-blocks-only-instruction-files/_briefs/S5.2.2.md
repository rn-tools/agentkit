# S5.2.2 — Decide: model-assisted review

## Goal

This is a decision story. Produce reproduction fixtures where a body rule
contradicts a block rule, with a test showing that `agentkit review` misses
them. Then write an options comparison for adding a model-assisted check. The
owner decides. Do not build any model step.

## Settled

- **Fixtures** go under the new `tests/fixtures/review/contradictions/`. Each is
  a complete instruction file. Its agentkit block is built with the real
  markers (`<!-- BEGIN rn-forge agentkit -->` /
  `<!-- END rn-forge agentkit -->`). Its body sits before the block and has no
  heading that the block also has.
    1. `model-choice.md`, from this machine. The block holds lines 10–12 and 18–19
       of `src/rn_forge/agentkit/assets/instructions/rules.md` at `96c4b0d`,
       verbatim, under their `##` headings from that file. Those lines say an
       implementer the user chooses (Codex, Sonnet or another model), and to
       pick the lowest-cost capable model. The body is the owner's earlier rule:

        ```markdown
        # Building stories

        - Always build a story with a Sonnet subagent; Opus reviews it. Never
          hand a story to Codex.
        ```

    1. `commit-policy.md`. The block says "Do not commit, push, or add
       dependencies unless explicitly asked." (line from `rules.md`, verbatim,
       under its heading). The body is
       `# Git\n\n- Commit after every green test run without asking.\n`.

    1. `validation-scope.md`. The block says "Run only the narrowest relevant
       format, lint, and tests for the changed scope." (verbatim from
       `rules.md`, under its heading). The body is
       `# Checks\n\n- Always run the full test suite after any edit.\n`.
- **Reproduction test.** Add `test_s5_2_2_contradictions_are_not_found` to
  `tests/test_review.py`. It is parametrized over the three fixtures. Each one
  is copied to the `home` fixture's `.claude/CLAUDE.md` and reviewed at
  machine scope, and the test asserts `review(...) == []`. Its docstring says
  it pins today's gap: a model step, if built, would make the test change.
- **Options comparison** goes in `## Result` as a table with one row per option:
    - **(a) No model:** keep `review` deterministic.
    - **(b) The agent CLI already installed:** `claude -p` or `codex exec`, fed
      the file and a fixed prompt, with an opt-in flag such as `review --model`.
    - **(c) A direct API call** through a provider SDK.
- The columns are: dependencies added (packages and programs), credentials and
  where they come from, run time per file, determinism and testability (how CI
  and the tests would stay offline), and failure modes. Take the facts from
  the code and from each CLI's `--help`. Running `claude --help` and
  `codex --help` is allowed. Never send a prompt to a model. Give run time as
  an estimate and state its basis. Add a final line with a recommendation and
  one sentence of reasoning. The owner makes the choice.

## Current behaviour

At `96c4b0d`, `review` checks headings, pointers, imports, placeholders and
markers only. None of the three fixtures has a duplicated heading, a pointer, a
placeholder phrase or bad markers, so `review` returns `[]` for each. The new
test passes as soon as it is written. That is the reproduction: it shows the
gap, not a fix. Before relying on it, confirm it passes. If any fixture yields a
suggestion, adjust the fixture's body wording (never `review.py`) until it
yields none, and note the change in `## Result`.
