# S5.2.1 — `agentkit review`

Brief for [S5.2.1](../F5.2-review-command.md#s521-agentkit-review), at
`cbd9bb1`.

## Goal

Add an advisory `agentkit review` command. It reads whole instruction files,
body included, and prints one suggestion per line. It never writes and always
exits 0. It is built on `src/rn_forge/agentkit/review.py`, which S5.1.2 created
with the old body checks and which no command calls yet.

## Settled

### Module `src/rn_forge/agentkit/review.py`

- Keep `PATHS`, which `instruction_checks.py` imports. Keep it unchanged.

- Replace `review_findings` with this public API:

    ```python
    @dataclass(frozen=True, slots=True)
    class Suggestion:
        """One advisory suggestion about an instruction file."""

        path: str
        line: int
        code: str
        message: str


    def review(target: Target) -> list[Suggestion]:
        """Return the suggestions for the target scope's instruction files."""
    ```

    `review` never raises for file content. A missing file is skipped. It reads
    each existing path in `PATHS[target.scope]` as UTF-8, in that order. Within
    a file, suggestions are sorted by `(line, code)`. Line numbers are 1-based
    in the file as it is on disk.

- Drop the `Finding` import and the old `agentkit.*` codes. Nothing else uses
  them after this story. `instruction_checks.py` keeps its own
  `agentkit.block-malformed` finding.

- **Regions.** Scan the file's lines once, tracking two things:

    - The region: `agentkit`, between the lines `<!-- BEGIN rn-forge agentkit -->`
      and `<!-- END rn-forge agentkit -->`; `kiln`, between
      `<!-- BEGIN rn-forge kiln -->` and `<!-- END rn-forge kiln -->`; or
      `body`, everywhere else. Compare a line with `.strip()`. Marker lines
      belong to no region.
    - Code fences: a line starting with ```` ``` ```` or `~~~` toggles a fence.
      Headings inside a fence are ignored, as `_headings` does today.

- A heading is `_HEADING`'s match, as today, with `.strip()` applied.

- **Malformed markers come first.** Call `BLOCK.extract(text)`. On
  `AppException`, emit only
  `Suggestion(path, 1, "review.block-malformed", "agentkit's block markers are malformed; run agentkit doctor")`
  for that file, and skip every other check for it. kiln's markers are not
  validated. Unbalanced kiln markers just extend the kiln region.

### Codes, and their exact messages

| Code | When | Line | Message |
| -- | -- | -- | -- |
| `review.heading-duplicated` | a body heading's text equals a heading in the agentkit or kiln region | the body heading | `heading {h!r} repeats one in agentkit's block` (or `kiln's block`; when both, say `agentkit's block`) |
| `review.heading-duplicated` | an agentkit-region heading's text equals a kiln-region heading | the agentkit heading | `heading {h!r} in agentkit's block repeats one in kiln's block` |
| `review.agents-points-at-claude` | the file's name is `AGENTS.md`, and a line outside fences matches `_CLAUDE_POINTER` | that line | `AGENTS.md points at CLAUDE.md, which Codex cannot follow` |
| `review.claude-import-missing` | the path is repository `CLAUDE.md`, and no line's `.strip()` equals `@AGENTS.md` | 1 | `CLAUDE.md does not import @AGENTS.md` |
| `review.import-repeated` | the path is repository `CLAUDE.md`, and a body line and an agentkit-region line both strip to `@AGENTS.md` | the first such body line | `@AGENTS.md is in both the body and agentkit's block; delete it from the body` |
| `review.placeholder` | a body line contains a pattern from `PLACEHOLDERS` (case-sensitive substring) | that line | `line still reads as template text: {pattern!r}` |

- One suggestion per duplicated body heading line, one per pointer line, and one
  per placeholder line. On one line, the first matching pattern wins.

- `_CLAUDE_POINTER` matches a Markdown link to `CLAUDE.md` and today's "Read
  `CLAUDE.md` now" phrasing:

    ```python
    _CLAUDE_POINTER = re.compile(r"\]\((?:\./)?CLAUDE\.md[)#]|[Rr]ead `CLAUDE\.md`")
    ```

- `PLACEHOLDERS: tuple[str, ...] = ("Replace this line", "Replace this section", "Instructions that only Claude Code should follow go here")`.
  These are kiln's old `AGENTS.md` and `CLAUDE.md` seed phrases.

- "Repository `CLAUDE.md`" means
  `target.scope is Scope.REPO and path == "CLAUDE.md"`. Machine
  `.claude/CLAUDE.md` gets neither the import checks nor
  `review.import-repeated`.

### Command

- In `src/rn_forge/agentkit/commands.py`, add `review`, with the same parameters
  and defaults as `plan` except `agent`:
  `def review(scope: Scope = Scope.MACHINE, repo: Path | None = None) -> None`,
  with the docstring
  `"""Suggest improvements to the scope's instruction files; never writes."""`.
  Import the module as `from rn_forge.agentkit import review as reviewing`,
  so its name does not clash with the command function.

- Text mode prints each suggestion as `{path}:{line}: {code} {message}` with
  `markup=False`, or `no suggestions` when there are none.

- JSON mode emits a list of `{"path", "line", "code", "message"}` objects, with
  `[]` when there are none.

- It never raises because of suggestions.

- Declare it in `.rn-forge/kiln/config.toml` after `plan`:

    ```toml
    [[cli.commands]]
    name = "review"
    target = "rn_forge.agentkit.commands:review"
    ```

    Then run `env -u VIRTUAL_ENV task kiln:apply` to regenerate
    `src/rn_forge/agentkit/cli.toml` (and `.rn-forge/kiln/state.json`). Never
    edit `cli.toml` by hand. This is how S4.2.1 added `migrate-v0` in `01f3fe8`.

## Current behaviour

At `cbd9bb1`:

- `agentkit review` is not a command, so `run(app, ["review"])` returns the
  usage-error exit code.
- `review.py` exposes `review_findings`, which returns `Finding`s with the
  `agentkit.*` codes, so
  `from rn_forge.agentkit.review import Suggestion, review` fails with
  `ImportError`.
- So every new test fails at collection.
