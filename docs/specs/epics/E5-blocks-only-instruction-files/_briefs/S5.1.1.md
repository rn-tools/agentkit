# S5.1.1 — `CLAUDE.md` import as a block

Brief for [S5.1.1](../F5.1-blocks-only.md#s511-claudemd-import-as-a-block), at
`9100c11`.

## Goal

At repository scope, agentkit writes the `@AGENTS.md` import into `CLAUDE.md` as
its own fenced block, instead of seeding a whole file. The body of an existing
`CLAUDE.md` is never touched.

## Settled

- In `src/rn_forge/agentkit/repository.py`:
    - Delete `CLAUDE_SEED`.
    - Add `CLAUDE_BODY = "@AGENTS.md\n"`.
    - In `render`, replace
      `Artifact("CLAUDE.md", ArtifactKind.SEEDED, CLAUDE_SEED)` with
      `Artifact("CLAUDE.md", ArtifactKind.BLOCK, CLAUDE_BODY, AGENTS_BLOCK)`.
      Reuse `AGENTS_BLOCK`: it is already
      `ManagedBlock("rn-forge agentkit", comment="<!--")`, the same name and
      comment the block needs. Do not add a second `ManagedBlock`.
    - Keep the artifact order: the optional `AGENTS.md` block, then `CLAUDE.md`,
      then `.gitignore`.
    - The `CLAUDE.md` block is appended unconditionally. It does not depend on
      `[repo]` keys. The `AGENTS.md` block keeps its `if body:` rule.
    - Update `render`'s docstring: "then a CLAUDE.md block that imports
      @AGENTS.md" in place of the seed sentence.
- The engine's BLOCK handling already does the rest. `ManagedBlock.render`
  appends an absent block at the end of the file, after a blank line, and
  keeps every byte outside the markers. It needs no engine change.
- Tests live in a new `tests/test_repository.py`. Delete
  `tests/test_claude_seed.py`: all four of its tests assert the seed behaviour
  that this story removes.

## Current behaviour

At `9100c11`, `CLAUDE.md` is a SEEDED artifact. Against that code, each new test
below fails:

- Absent file: `apply` writes exactly `@AGENTS.md\n`, with no markers, so a byte
  comparison with the marked block fails.
- File with a body: `apply` reports `skip` for `CLAUDE.md` and leaves the file
  unchanged, so the assertion that the block was appended fails.
- `plan`: the `CLAUDE.md` row's action is `skip` and its kind is `seeded`, not
  `insert` and `block`.

## Tests first

Write `tests/test_repository.py` and copy the `home` and `repo` fixtures, plus
`KILN_AGENTS` and `_state`, from `tests/test_claude_seed.py` at `9100c11`. The
expected block, with
`M = "<!-- BEGIN rn-forge agentkit -->\n@AGENTS.md\n<!-- END rn-forge agentkit -->\n"`:

1. `test_s5_1_1_absent_claude_md_gets_only_the_block`: with no `CLAUDE.md`,
   `apply --scope repo --repo <repo>` exits OK, and `CLAUDE.md` equals `M`
   byte for byte. The state entry for `CLAUDE.md` has kind
   `ArtifactKind.BLOCK`.
1. `test_s5_1_1_body_is_kept_byte_for_byte`: `CLAUDE.md` holds
   `"# Claude\n\nNotes.\n"`. After `apply`, the file starts with exactly those
   bytes, the rest is `"\n" + M`, and the block extracts to `"@AGENTS.md\n"`.
   A second `apply` leaves the file unchanged.
1. `test_s5_1_1_body_with_import_still_gets_block`: the body is
   `"@AGENTS.md\n\n## Claude-only\n"`. After `apply` the body bytes are
   unchanged, and the block is appended as in test 2.
1. `test_s5_1_1_plan_inserts_block_without_conflict`: the body is
   `"# Claude\n"`. `--json plan --scope repo --repo <repo>` exits OK. Its
   `changes` row for `CLAUDE.md` is `{"action": "insert", "kind": "block"}`
   (compare those two fields), and no row has action `conflict`.
1. `test_s5_1_1_block_written_without_repo_keys`: no overlay at all. `apply`
   creates `CLAUDE.md`, and `AGENTS.md` still has no `rn-forge agentkit` block
   (it keeps `KILN_AGENTS` unchanged).
1. `test_s5_1_1_remove_takes_block_keeps_body`: the body is `"# Claude\n"`.
   After `apply` then `remove --scope repo --repo <repo>`, `CLAUDE.md` equals
   `"# Claude\n"` exactly. The engine strips a block and its separator, as
   `tests/test_remove.py::test_s1_3_3_remove_deletes_managed_and_strips_blocks`
   shows. For a file that held only the block, assert only that `remove`
   exits OK; it does not delete the file.
