An advisory command that reads a whole instruction file, including its body, and
suggests improvements. It never writes, always exits 0, and no `task` verb or
gate runs it.

## S5.2.1 — `agentkit review`

**State:** Closed (2026-11-22)

**Acceptance:**

- `agentkit review` is declared in `cli.toml` and runs at the same scope as
  `plan`: machine by default, repository inside a repository. It reads
  `~/.claude/CLAUDE.md` and `~/.codex/AGENTS.md`, or the repository's
  `AGENTS.md` and `CLAUDE.md`.
- Each suggestion prints as one line: the file, the line number, a code and a
  sentence. The codes are:
    - `review.heading-duplicated`: a body heading repeats a heading in a block, or
      a heading in agentkit's block repeats one in kiln's block.
    - `review.agents-points-at-claude`: `AGENTS.md` links or points to
      `CLAUDE.md`, which Codex cannot follow.
    - `review.claude-import-missing`: a repository `CLAUDE.md` with no
      `@AGENTS.md` anywhere, for example because its owner removed agentkit's
      block.
    - `review.import-repeated`: `@AGENTS.md` appears both in the body and in
      agentkit's block.
    - `review.placeholder`: a body line still reads as template text. The patterns
      kiln's old `AGENTS.md` and `CLAUDE.md` seeds left behind are listed in one
      constant, starting with the phrase "Replace this line".
- With nothing to suggest, `review` prints `no suggestions`. The exit code is 0
  either way, and on malformed markers too, which `review` reports as a
  suggestion that points to `doctor`.
- Step 7 of `docs/runbooks/cutover-from-v0.md` uses `agentkit review` in place
  of `agentkit doctor` to find duplicated body text.
- Tests in `tests/test_review.py` hold one fixture per code, plus a clean
  fixture that yields `no suggestions`. The tests moved from
  `tests/test_instruction_checks.py` keep their cases.
- On this repository, `review --scope repo` reports kiln's five leftover
  placeholder lines; machine scope reports `no suggestions`.

## S5.2.2 — Decide: model-assisted review

**State:** Closed (2026-11-22) · **Depends on:** S5.2.1

**Acceptance:**

- Reproduction fixtures where a body rule contradicts a block rule. One is from
  this machine: the body asks for one model, and the block asks for another.
  The heading checks find nothing in them.
- An options comparison in the story's outcome: no model; a model reached
  through the agent CLI already installed (`claude -p` or `codex exec`); or a
  direct API call. Each option is costed in dependencies, credentials, run
  time and determinism.
- The owner's choice is recorded on this feature. If it adds a model step, the
  choice includes the story that builds it.

**Outcome:** the three fixtures in `tests/fixtures/review/contradictions/`
return no suggestions; the test pins that gap.

| Option | Adds | Credentials | Run time per file | Determinism |
| -- | -- | -- | -- | -- |
| (a) No model | nothing | none | under 10 ms | deterministic, offline |
| (b) `claude -p` or `codex exec` | a program on `PATH` | the CLI's login | 2–30 s | varies; tests mock the subprocess |
| (c) Provider API | an SDK dependency | an API key | 1–20 s | varies; tests fake the client |

**Decision (owner, 2026-11-22):** (a). `review` stays deterministic and makes no
model call, so no build story follows.
