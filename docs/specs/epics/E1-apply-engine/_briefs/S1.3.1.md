# S1.3.1 — apply and diff

Brief for [S1.3.1](../F1.3-commands.md#s131-apply-and-diff), at `370af4c`.

## Goal

Add the `agentkit apply` and `agentkit diff` commands. Each resolves a scope
(machine or repository), loads the layered config (S1.1.1), renders artifacts
through an adapters seam, and plans against the scope's state with the commons
generation engine. `apply` then writes transactionally; `diff` only shows. The
seam renders nothing until F1.4. This story's tests stub it with managed and
block artifacts.

## Settled

- **No logic in the CLI layer** (F1.3): `commands.py` functions parse options
  and print. Everything else lives in `operations.py`.
- **Scope target** (F1.3 Design, S1.1.1):
    - Machine scope: root is `Path.home()`, and the work dir is
      `<rnf_home>/share/agentkit/`.
    - Repository scope: root is `--repo PATH` when given, else the git top level
      of the current directory, from `git rev-parse --show-toplevel` run with
      `cwd`. Outside a git repository it raises
      `AppException("not inside a git repository: {}", cwd)`. The work dir is
      `<root>/.rn-forge/agentkit/`.
    - In both scopes: state is `<work dir>/state.json`, backups go under
      `<work dir>/backups/`, staging is `<work dir>/.staging/`, and the user
      overlay is `user_overlay_path(rnf_home)`. The repository overlay is
      `repo_overlay_path(root)`, and only repository scope reads it
      (`load_sources` already ignores it at machine scope).
    - `rnf_home` comes from `rn_forge.tooling.install.rnf_home()`.
- **State store:** `StateStore(path, entry_type=StateEntry)` from commons, with
  the default `schema_version`.
- **Engine:** `rn_forge.commons.generation`'s
  `plan(root, artifacts, entries, force=...)`,
  `apply(root, planned, store, staging_dir=..., backup_dir=..., entries=..., dry_run=...)`
  and `diff(root, change)`. Do not reimplement classification, backups or
  rollback. `apply` already refuses unapproved blocking changes, listing each
  `path (action)` (`Plan.check`), and backs up under
  `<backup_dir>/<UTC stamp>/`.
- **Options:**
    - `--scope machine|repo`, default `machine`.
    - `--repo PATH`.
    - `--agent claude|codex`, repeatable, default both.
    - `--force PATH`, repeatable; apply only.
    - `--dry-run`; apply only, using `rn_forge.cli.DryRunOption`.
    - `--json` is the root flag (`agentkit --json diff`). A command checks
      `console.mode is OutputMode.JSON`
      (`from rn_forge.commons.runtime.console import OutputMode, console`). Do
      not import `typer`: the import-linter contract forbids it. Plain
      parameters with defaults become options, and `list[...] | None = None` is
      repeatable.
- **Output:**
    - `apply` prints one line per change, `<action> <path>`. In JSON mode it emits
      `[{"path", "kind", "action"}, ...]` via `console.emit`.
    - `diff` prints `diff(root, change)` for each change whose action is in
      commons `WRITE_ACTIONS`. In JSON mode it emits the same list as `apply`,
      for every change.
- **Exit codes:** a blocked plan raises the commons `AppException`, which
  `rn_forge.cli.run` maps to exit 1. Success is 0.
- **CLI wiring:** commands are declared in `.rn-forge/kiln/config.toml`
  `[[cli.commands]]` and rendered into the generated
  `src/rn_forge/agentkit/cli.toml` by `task kiln:apply`. That config file is
  hand-authored and you may edit it. `cli.toml` you must not edit by hand. The
  kiln `hello` stub goes: remove its `[[cli.commands]]` entry, the function
  and its tests.

## Current behaviour

- `src/rn_forge/agentkit/commands.py:14-16` holds only `hello`.
  `.rn-forge/kiln/config.toml` declares one command, `hello`, under `[cli]`.
- `tests/test_cli.py:14-24` tests `hello`. The other two tests use `hello` as
  the known command: the unknown-command test and the missing-argument test.
- `src/rn_forge/agentkit/sources.py` has `Scope`, `load_sources`,
  `user_overlay_path` and `repo_overlay_path`, all used as they are.
- There is no `operations.py`, `targets.py` or `adapters.py`. The new tests fail
  at collection with `ImportError`, or with exit 2 (`No such command 'apply'`)
  for tests that only go through the CLI.

## Change

- **Change:**
    - New `src/rn_forge/agentkit/targets.py`:
        - `class Agent(StrEnum)`: `CLAUDE = "claude"`, `CODEX = "codex"`.
        - `@dataclass(frozen=True, slots=True) class Target` with fields
          `scope: Scope`, `root: Path`, `work_dir: Path` and `rnf_home: Path`.
          Properties: `state_path`, `backup_dir`, `staging_dir`, `user_overlay`
          (`user_overlay_path(rnf_home)`) and `repo_overlay`
          (`repo_overlay_path(root)`).
        - `def resolve_target(scope: Scope, *, repo: Path | None, cwd: Path, home: Path, rnf_home: Path) -> Target`,
          implementing the rules above. Use
          `Process.execute("git", "git", "rev-parse", "--show-toplevel", cwd=cwd, fail_on_error=False)`
          from `rn_forge.commons.runtime.subprocess`, and read its exit status
          and stdout.
    - New `src/rn_forge/agentkit/adapters.py`:
        - `def render(target: Target, agents: Sequence[Agent], sources: MergeResult) -> list[Artifact]`,
          returning `[]`. Its docstring says F1.4's adapters fill it. Nothing else
          goes in this module.
    - New `src/rn_forge/agentkit/operations.py`:
        - `def build_plan(target: Target, agents: Sequence[Agent], *, force: Sequence[str] = ()) -> tuple[Plan, dict[str, StateEntry]]`:
          loads sources, calls `adapters.render` as a module attribute so tests
          can monkeypatch it, loads state, and returns
          `(plan(target.root, artifacts, entries, force=force), entries)`.
        - `def run_apply(target, agents, *, force=(), dry_run=False) -> ApplyResult`:
          calls `build_plan` then commons `apply`, passing `entries`.
        - `def run_diff(target, agents) -> tuple[Plan, list[str]]`: returns the plan
          and the non-empty unified diffs of its write changes.
    - `src/rn_forge/agentkit/commands.py`: replace `hello` with `apply` and
      `diff`, thin over `operations` and `resolve_target`. They pass
      `home=Path.home()`, `cwd=Path.cwd()` and `rnf_home=rnf_home()`. An absent
      `--agent` means `list(Agent)`.
    - `.rn-forge/kiln/config.toml`: replace the `hello` `[[cli.commands]]` with
      `apply` → `rn_forge.agentkit.commands:apply` and `diff` →
      `rn_forge.agentkit.commands:diff`. Then run `task kiln:apply`.
    - `tests/test_cli.py`: drop `hello`'s test. Point the unknown-command and
      missing-argument tests at the new surface. For a missing argument, use
      `apply --scope` with no value, which is a usage error (exit 2).
    - New `tests/test_targets.py` and `tests/test_apply.py` (below).
    - Docstrings on every public name.
- **Leave alone:** `sources.py`, `product.py`, `main.py`, and every
  kiln-generated file except what `task kiln:apply` rewrites. Also
  `pyproject.toml`, `uv.lock`, and every doc page except this brief's
  `## Result`.

## Tests first

All CLI tests go through `rn_forge.cli.run(app, [...])`, with `app` from
`rn_forge.agentkit.main`, as `tests/test_cli.py` does. They share a fixture:

- `monkeypatch.setenv("HOME", str(tmp_path / "home"))` and
  `monkeypatch.setenv("RNF_HOME", str(tmp_path / "home" / ".rn-forge"))`.
- The adapters seam stubbed with
  `monkeypatch.setattr(adapters, "render", lambda target, agents, sources: ARTIFACTS)`.
  `ARTIFACTS` is a managed
  `Artifact(".agent/one.md", ArtifactKind.MANAGED, "one\n")` and a block
  `Artifact(".agent/rules.md", ArtifactKind.BLOCK, "rule\n", ManagedBlock("rn-forge agentkit"))`.
  Check `ManagedBlock`'s constructor in `rn_forge.commons.fs.blocks`; an
  HTML comment style suits Markdown.
- A `tree_hash(path)` helper hashing every file's relative path and bytes under
  the temp home.

`tests/test_apply.py`:

1. `test_s1_3_1_dry_run_and_diff_write_nothing`: `apply --dry-run` and `diff`
   both exit 0, and `tree_hash` is identical before and after.
1. `test_s1_3_1_drift_blocks_and_writes_nothing`: apply, edit `.agent/one.md` by
   hand, then apply again. The exit is 1, the captured output names
   `.agent/one.md` and `drift`, and `tree_hash` is unchanged by the second
   run.
1. `test_s1_3_1_force_approves_only_the_named_path`: drift both files. Then
   `apply --force .agent/one.md` exits 1 naming `.agent/rules.md`, and
   `apply --force .agent/one.md --force .agent/rules.md` exits 0 with both
   files restored to the render.
1. `test_s1_3_1_overwritten_files_are_backed_up_first`: after the forced apply
   in the previous test's shape,
   `<RNF_HOME>/share/agentkit/backups/*/.agent/one.md` exists and holds the
   hand-edited text.
1. `test_s1_3_1_diff_prints_unified_and_json_lists_the_plan`:
    - On a fresh home, `diff` output contains `+++ .agent/one.md`.
    - `--json diff` stdout parses as a JSON list whose items have exactly the
      keys `path`, `kind` and `action`, and which includes
      `{"path": ".agent/one.md", "kind": "managed", "action": "create"}`.
1. `test_s1_3_1_second_apply_is_all_unchanged`: apply twice. The second run
   exits 0, and in `--json` mode every item's action is `unchanged`.
1. `test_s1_3_1_machine_state_lives_in_the_share_dir`: after apply,
   `<RNF_HOME>/share/agentkit/state.json` exists, and nothing is written under
   `.rn-forge/agentkit/` in the home.

`tests/test_targets.py`:

1. `test_s1_3_1_repo_scope_uses_the_git_top_level`: `git init` a temp repo (via
   `Process.execute`), make a subdirectory, and call
   `resolve_target(Scope.REPO, repo=None, cwd=<subdir>, ...)`. Assert `root`
   is the repo, resolved, and `state_path` is
   `<repo>/.rn-forge/agentkit/state.json`.
1. `test_s1_3_1_repo_flag_overrides_cwd`: with `repo=<dir>`, root is that
   directory and git is not consulted. A non-repository directory is accepted.
1. `test_s1_3_1_repo_scope_outside_git_fails`: `cwd` is a non-git temp
   directory, and `pytest.raises(AppException)` with the cwd in its message.
1. `test_s1_3_1_machine_target_paths`: root is `home`, the work dir is
   `rnf_home/share/agentkit`, and the backup, staging and overlay paths are as
   settled.
