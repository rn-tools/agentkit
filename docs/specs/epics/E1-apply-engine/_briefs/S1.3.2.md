# S1.3.2 — plan and findings

Brief for [S1.3.2](../F1.3-commands.md#s132-plan-and-findings), at `dd42789`.

## Goal

Add `agentkit plan`: the per-artifact table, from the same plan `apply` uses,
plus the scope's findings. Machine-scope findings also run in the lifecycle
`agentkit doctor`, through `ToolProduct.checks()`.

## Settled

- **Same plan** (F1.3 Design): `plan` calls `operations.build_plan`, exactly
  what `run_apply` calls. Nothing classifies twice.

- **Findings** are commons `Finding(code, severity, message)` from
  `rn_forge.commons.findings`, in a new module, `findings.py`:

    | Code | Severity | When | Scope |
    | -- | -- | -- | -- |
    | `agentkit.agent-missing` | WARNING | `shutil.which(<agent>)` is `None`, for each selected agent (`claude`, `codex`), naming it | machine |
    | `agentkit.jq-missing` | ERROR | `shutil.which("jq")` is `None` (the hooks need it) | machine |
    | `agentkit.gitleaks-missing` | WARNING | `shutil.which("gitleaks")` is `None` | machine |
    | `agentkit.state-file-gone` | WARNING | a state entry whose file, `target.root / entry.path`, does not exist; the message names the path | both |
    | `agentkit.overlay-invalid` | ERROR | an overlay raises `DocumentError` or `SourceError` from `load_overlay`; the message is that exception's `.message`, which starts with the path. Machine scope checks the user overlay; repository scope checks it and the repository overlay | both |

- **One `jq` check:** `check_jq` moves from `product.py` to `findings.py`,
  unchanged. `Tool.checks()` becomes `(check_share_dir, check_machine)`, so
  `doctor` reports `jq` once, via `check_machine`. S4.1.1's
  `test_s4_1_1_lifecycle_doctor_reports_both_errors` must still pass
  unchanged. Only the import lines in `tests/test_product.py` change.

- **`check_machine(home: ToolHome) -> list[Finding]`** is in `findings.py`. It
  resolves
  `resolve_target(Scope.MACHINE, repo=None, cwd=Path.cwd(), home=Path.home(), rnf_home=home.root)`
  and returns `scope_findings(target, list(Agent))`.

- **`scope_findings(target: Target, agents: Sequence[Agent]) -> list[Finding]`**
  returns the "both" rows for any scope, plus the "machine" rows when
  `target.scope is Scope.MACHINE`.

- **The `plan` command:**

    - Options: `--scope`, `--repo` and `--agent`, as for `diff`.
    - It computes findings first. If any is `agentkit.overlay-invalid`, it prints
      the findings and fails without building the plan, because the plan cannot
      load the sources.
    - Otherwise it builds the plan.
    - Text output: one line per change, `<action> <kind> <path>`, then one line
      per finding, `<severity> <code> <message>`.
    - JSON output (root `--json`): one object,
      `{"changes": [{"path","kind","action"}, ...], "findings": [finding.as_dict(), ...]}`,
      via `console.emit`.
    - Exit: if any finding is `Severity.ERROR`, raise
      `AppException("{} error finding(s)", n)` after printing, which gives exit
      1\. Otherwise exit 0, warnings and blocking changes included: `plan`
      reports and does not refuse.

- **Wiring:** add `[[cli.commands]] name = "plan"`,
  `target = "rn_forge.agentkit.commands:plan"` to
  `.rn-forge/kiln/config.toml`, after `diff`. Then run `task kiln:apply`.

- **Comparing plan with `apply --dry-run`:** commons `apply` checks the plan
  before honouring `dry_run`. So `apply --dry-run` on a drift or missing
  fixture exits 1, naming `<path> (<action>)`, rather than printing its plan.
  The tests compare against that message.

## Tests first

`tests/test_plan.py`. Reuse the `home` fixture shape and `ARTIFACTS` from
`tests/test_apply.py`: copy them, and do not import across test modules. Stub
`shutil.which` through `rn_forge.agentkit.findings` with a dict-backed function,
so each test chooses which programs exist. Default to all present.

1. `test_s1_3_2_plan_matches_apply_across_states`, parametrized over `create`,
   `unchanged`, `drift` and `missing`:
    - For `unchanged`, `drift` and `missing`, first apply; then edit or delete
      `.agent/one.md` for the last two.
    - `--json plan` gives one action per path. `.agent/one.md`'s action equals
      the parameter.
    - For `create` and `unchanged`, the full action list equals
      `apply --dry-run --json`'s.
    - For `drift` and `missing`, `apply --dry-run` exits 1 and its output
      contains `.agent/one.md (<action>)`.
1. `test_s1_3_2_error_finding_exits_1_warnings_exit_0`:
    - Only `jq` missing: `plan` exits 1, and `--json plan` findings include
      `agentkit.jq-missing` at `error`.
    - Only `gitleaks` and `codex` missing: exits 0, with
      `agentkit.gitleaks-missing` and `agentkit.agent-missing` at `warning`.
1. `test_s1_3_2_state_entry_whose_file_is_gone`: apply, delete `.agent/one.md`,
   then `--json plan`. Findings include `agentkit.state-file-gone` naming
   `.agent/one.md`.
1. `test_s1_3_2_invalid_overlay_is_an_error_with_its_path`: write `[claude` to
   `<RNF_HOME>/share/agentkit/config.toml`. `plan` exits 1, and its output
   contains that path and `agentkit.overlay-invalid`.

   `jq` stubbed missing. `plan --scope repo --repo <repo>` exits 0, and no
   finding code is `jq-missing`, `gitleaks-missing` or `agent-missing`.
1. `test_s1_3_2_doctor_runs_machine_findings`: with `jq` and `claude` missing,
   `rn_forge.tooling.install.doctor(PRODUCT, home=ToolHome("agentkit", <RNF_HOME>))`
   includes `agentkit.jq-missing` exactly once and `agentkit.agent-missing`
   naming `claude`.
