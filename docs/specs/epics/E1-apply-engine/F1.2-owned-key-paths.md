An artifact kind for "these key paths inside a JSON or TOML file the app also
writes".

## Context

`rn_forge.commons.generation` has managed, seeded and block artifacts only.
[ADR-0003](../../../adr/ADR-0003.md) needs key-path ownership, so something has
to add it.

## Design

The commons kind S1.2.1 chose. It is stated here in full so the commons change
can be specified from it:

- `ArtifactKind.KEYS`: the generator owns named dotted key paths inside a JSON
  or TOML file that another program also writes.
- Its state entry records the owned key paths and a hash of their canonical
  values. Unowned keys are never hashed.
- Plan classification:
    - Owned values equal to the recorded ones: `unchanged`.
    - Owned values differ from the recorded ones: `drift`.
    - File present with no entry: `insert`.
    - File absent: `create`, containing only the owned keys.
    - A stale entry, or a path dropped from the render: `remove` of those keys
      only, never a file delete.
- Apply writes through the existing staging, backup and rollback. TOML keeps
  comments and order (round-trip), and JSON uses the existing writer.
- A list value is compared whole.

## S1.2.1 — Decide where the key-path kind lives

**State:** Closed (2026-11-19)

A decision story. Its brief asks for a spike comparing (a) a `keys`
`ArtifactKind` added to rn-forge-commons `generation` (classify, apply and
`StateEntry` carry owned paths and a value hash) against (b) an agentkit-local
classifier that produces commons `Change`s and records its own state entries.
The comparison covers lines of code, whether kiln could reuse it, release
coupling (a commons release plus an agentkit pin bump), and rollback guarantees
under apply's transaction. The brief's recommendation is (a). The owner decides;
the outcome is recorded on this feature under *Considered and rejected* and, if
(a), as an entry criterion "rn-forge-commons release with the keys kind exists"
on S1.2.2.

**Acceptance:**

- The comparison and the owner's choice are recorded on this feature.

Outcome: the owner chose (a), a `keys` kind in rn-forge-commons (2026-11-19).

## S1.2.2 — Key-path artifacts plan and apply

**State:** New · **Depends on:** S1.2.1

**Entry criteria:** `rn-forge-commons` 0.10.1, which has `ArtifactKind.KEYS`, is
on PyPI. S1.2.2 moves agentkit's floor to `rn-forge-commons>=0.10.1,<0.11`.

**Acceptance:**

- File present with no state entry (the first apply over an app-written settings
  file): apply inserts the owned keys without `--force`, as a block insert
  does; unowned keys are untouched.

- JSON is written with sorted keys and two-space indent (the commons writer);
  values of unowned keys are unchanged, their order is not kept.

- JSON and TOML both: apply sets owned paths and leaves every other key
  byte-identical in value; TOML comments outside owned tables survive (test
  with a commented TOML fixture).

- Adding an unowned key on disk after apply: the plan shows `unchanged` for the
  artifact.

- Changing an owned value on disk: the plan shows `drift`; apply refuses without
  `--force <path>`; with it, the file is backed up and the owned value
  restored.

- A key path dropped from the render is removed from the file on the next apply
  and from state.

- A list value is compared whole: appending an item by hand is drift.

- File absent: `create` writes a file containing only owned keys.

## Acceptance

```bash
set -euo pipefail

task test -- tests/test_keys.py   # S1.2.2: all six lines above
```

S1.2.1 cannot be scripted: the owner reads the recorded comparison and makes the
choice.

## Considered and rejected

- **(b) An agentkit-local key-path classifier over commons 0.10.0.** Rejected
  (owner, 2026-11-19, from the S1.2.1 comparison). Commons treats every
  non-block state entry as a whole file. So dropping a file's last owned key,
  or `agentkit remove`, plans a delete of the whole `settings.json`, and a
  probe confirmed that forcing it deletes the file. Avoiding that means
  intercepting stale entries in every plan consumer, and keeping the key-path
  list in a second state store that apply's rollback does not cover. That
  breaks ADR-0004's single classification and its "no state code of our own".
  The two options were about the same size.
