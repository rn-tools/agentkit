Loading and merging the packaged defaults, the user overlay and the repository
overlay into one config per agent, with each key's winning layer.

## Design

The overlay TOML shape is one table per agent: `[claude]`, `[codex]`, and
`[repo]` for repository-scope values (worktree root, commit rules; see
[F2.2](../E2-instruction-files/F2.2-repository-block.md)). Packaged defaults
ship as `src/rn_forge/agentkit/defaults/<agent>.toml`.

- **Merge:** tables merge recursively; every other value (scalars, lists)
  replaces.
- **Provenance:** a map from dotted key to layer name (`packaged`, `user` or
  `repo`).
- **Missing overlay file:** an empty layer.
- **Unknown top-level table:** an error naming the table and the file.

## S1.1.1 — Load and merge the three layers

**State:** New

**Acceptance:**

- `tests/test_sources.py`: a key set in all three layers takes the repo value;
  provenance names `repo`.
- A list in the user overlay replaces the packaged list (not appended); the test
  asserts the exact list.
- Nested tables merge: packaged `a.b=1` and user `a.c=2` give `{a:{b:1,c:2}}`.
- Absent overlay files load as empty layers; an unknown top-level table fails
  with the file path and table name in the message.
- Machine scope ignores the repo overlay even when run inside a repository.
