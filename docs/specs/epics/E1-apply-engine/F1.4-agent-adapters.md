A Claude adapter and a Codex adapter as data: each declares, per scope, its
artifact list (path relative to the scope root, kind, source or template,
executable bit) and the settings key paths it owns. Built-ins only; entry-point
plugin discovery is not in v1 (parked as an idea).

## Context

Split on 2026-11-20 (owner). S1.4.1 builds the adapter seam with whole-file and
block artifacts, so that F2.1, F3.1 and F3.2 can start before `rn-forge-commons`
0.10.1. S1.4.2 adds the two settings artifacts, which need the `keys` kind, and
depends on
[S1.2.2](F1.2-owned-key-paths.md#s122-key-path-artifacts-plan-and-apply).

## Design

**Seam.** `rn_forge.agentkit.adapters.render(target, agents, sources)` (F1.3)
returns the selected adapters' artifacts for the target's scope. Each adapter is
a module of plain data. Per scope, it lists its artifact specs: path relative to
the scope root, kind, source or template, and an executable flag. Commons
`Artifact` has no file mode, so `run_apply` passes commons `apply` a `verify`
callback that sets every executable artifact's file to mode 0755. A failure
there rolls the whole apply back.

Owned settings keys come from packaged defaults, with values ported from the old
agentkit defaults
(`rn_backup/agentkit/src/rn_forge/agentkit/agents/{claude,codex}/defaults/global.*`).

**Claude, `~/.claude/settings.json`**

- Owned: `permissions.deny` (the 21 secret-file Read globs), `hooks`,
  `outputStyle`, `effortLevel`, `extraKnownMarketplaces`.
- Not owned: `model`, `availableModels`, `modelSettings`, notification and
  remote flags, `env`, `permissions.allow`, `permissions.ask`.

**Codex, `~/.codex/config.toml`**

- Owned: `personality`, `approval_policy`, `sandbox_mode`,
  `model_reasoning_effort`, `model_reasoning_summary`, `features.hooks`,
  `sandbox_workspace_write.network_access`, `profiles.trusted`,
  `profiles.deep`.
- Not owned: `model`, `notify`, `mcp_servers`, `plugins`, `marketplaces`,
  `projects`, `desktop`, `hooks.state`.

## S1.4.1 — Adapter seam with file and block artifacts

**State:** New

**Acceptance:**

- Each adapter's artifact list is plain data. A test asserts that no two
  artifacts across adapters share a destination.
- `adapters.render` returns only the selected agents' artifacts for the target's
  scope. With no content packaged yet, a test adapter fixture proves that
  managed, seeded and block specs render into commons `Artifact`s.
- An executable spec's file is mode 0755 after `apply`, and a failing chmod
  rolls the apply back.
- A path that would escape the scope root is rejected at load.

## S1.4.2 — The two settings artifacts

**State:** New · **Depends on:** S1.2.2

**Acceptance:**

- Against fixtures copied from the shape of a real 2026-11-14 `settings.json`
  and `config.toml`, with the unowned keys above present, apply changes only
  the owned paths. Every unowned key above is asserted unchanged.
- An owned key the user overlay sets, for example
  `[claude] effortLevel = "high"`, is applied.
