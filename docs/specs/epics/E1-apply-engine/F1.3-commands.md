`agentkit apply`, `diff`, `plan` and `remove`, each with `--scope machine|repo`
(default `machine`; `repo` uses the git root of the current directory, or
`--repo PATH`), `--agent claude|codex` (repeatable, default all), and the
rn-forge-cli standard `--json`. Commands are thin over operations; no logic
lives in the Typer layer.

## Context

The commands work on whatever artifacts the adapters render: managed, seeded and
block artifacts now, and key-path artifacts once
[S1.2.2](F1.2-owned-key-paths.md#s122-key-path-artifacts-plan-and-apply) lands.
So F1.3 depends only on F1.1 (owner, 2026-11-19), and its tests render managed
and block artifacts. Until [F1.4](F1.4-agent-adapters.md), the adapters seam
(`rn_forge.agentkit.adapters.render`) renders nothing.

## Design

**Settled naming.** The lifecycle surface from `build_tool_app` already owns
`install upgrade uninstall cleanup status doctor`, so agentkit adds no `status`
or `doctor` verb. `plan` is the per-artifact status table plus the scope's
findings. Machine-scope findings also run in the lifecycle `doctor`, through
`ToolProduct.checks()` (a `Check` is `Callable[[ToolHome], Iterable[Finding]]`,
so it can only see machine scope). Repo-scope findings are reported by
`plan --scope repo` only.

**State.** Machine scope keeps `state.json` in the share dir
(`$RNF_HOME/share/agentkit/`); repo scope keeps it in
`<repo>/.rn-forge/agentkit/state.json` (committed). Backups and staging live in
the share dir for machine scope, and in
`<repo>/.rn-forge/agentkit/{backups,.staging}/` for repo scope (gitignored; see
[S2.2.3](../E2-instruction-files/F2.2-repository-block.md)).

## S1.3.1 — apply and diff

**State:** Closed (2026-11-19)

**Acceptance:**

- `apply --dry-run` and `diff` write nothing (the test asserts the temp HOME
  tree is unchanged by hash).
- `apply` with any drift, conflict or missing artifact exits non-zero and lists
  each blocking path with its action; nothing is written.
- `apply --force <path>` (repeatable) approves only the named paths; others
  still block.
- Every overwritten or deleted file is copied under `<backups>/<UTC timestamp>/`
  first.
- `diff` prints a unified diff per changed artifact; `--json` emits the plan as
  a list of `{path, kind, action}`.
- A second `apply` right after the first reports every artifact `unchanged` and
  exits 0.
- Contract: the scope resolves to `targets.Target`. At machine scope the root is
  `$HOME` and the work dir is `$RNF_HOME/share/agentkit/`. At repository scope
  the root is `--repo` or the git top level, and the work dir is
  `<root>/.rn-forge/agentkit/`. Artifacts come from
  `adapters.render(target, agents, sources)`. `--json` is the root flag.

Outcome: built on commons `plan`/`apply`/`diff`; the kiln `hello` stub is gone.

## S1.3.2 — plan and findings

**State:** Closed (2026-11-20) · **Depends on:** S1.3.1

**Acceptance:**

- `plan` lists every artifact with kind and action, from the same plan `apply`
  would use (test: plan action equals `apply --dry-run` action for each
  artifact across create, unchanged, drift and missing fixtures).
- Findings are rn-forge commons `Finding`s; `plan` exits 1 on any error-severity
  finding, 0 with warnings only.
- Machine-scope findings: agent binary not on PATH (warning), `jq` absent
  (error; the hooks need it), `gitleaks` absent (warning), state entries whose
  file is gone, overlay files that fail to parse (error with path).
- The same machine-scope findings appear in the lifecycle `agentkit doctor`
  output (test through `ToolProduct.checks()`).
- Contract: the finding codes are `agentkit.agent-missing`,
  `agentkit.gitleaks-missing` and `agentkit.state-file-gone` (warnings), and
  `agentkit.jq-missing` and `agentkit.overlay-invalid` (errors). `--json plan`
  emits `{"changes": [...], "findings": [...]}`. Repo scope skips the program
  checks. `doctor` reaches them through `findings.check_machine`, which
  reports `jq` once.

Outcome: `check_jq` moved from `product.py` to `findings.py`.

## S1.3.3 — remove

**State:** Closed (2026-11-20) · **Depends on:** S1.3.1

**Acceptance:**

- `remove --scope machine` deletes managed files, removes agentkit blocks and
  owned key paths, and leaves bodies and unowned keys intact; each touched
  file is backed up first.
- A managed file whose content drifted is left in place and reported, not
  deleted.
- It asks before deleting the share dir; `--yes` skips the prompt; without
  either, the share dir stays.
- After `remove`, `plan` shows nothing recorded.
- The README's uninstall section says to run `remove` before the lifecycle
  `uninstall` (test greps the README).
- Contract: `remove` takes `--scope`, `--repo` and `--yes`, with no `--agent`:
  state entries carry no agent until F1.4, so it takes back the whole scope. A
  drifted file is left in place, dropped from state, and reported under
  `left`, with exit 0. The share-dir prompt is machine scope only.

Outcome: `remove` is commons `plan(root, [], entries)` minus its blocking
changes.
