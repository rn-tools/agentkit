# S4.1.1 — Product declaration and checks

Brief for
[S4.1.1](../F4.1-product-and-install.md#s411-product-declaration-and-checks), at
`f6f2cd5`.

## Goal

Give `product.py` agentkit's real lifecycle `doctor` checks: the share dir is
writable, and `jq` is on `PATH`. Then prove that agentkit installs from a local
archive, runs `--version` from its link, and leaves the share dir in place on
uninstall.

## Settled

- **Share dir** (F1.3 Design; S1.1.1): `<rnf_home>/share/agentkit/`, where
  `<rnf_home>` is `ToolHome.root`. It is not under `ToolHome.product_dir`,
  which `uninstall` deletes. That is why the user overlay and state live
  there.
- **Writable** means one of two things:
    - The share dir exists, is a directory, and passes `os.access(path, os.W_OK)`.
    - It does not exist, and its nearest existing ancestor is a directory that
      passes `os.access(ancestor, os.W_OK)`. A fresh machine with no share dir
      yet is not an error.
- **Finding codes and severity:** `agentkit.share-unwritable` and
  `agentkit.jq-missing`, both `Severity.ERROR`. The message names the path or
  the program. Each check returns `[]` when all is well.
- **The `check_home` INFO check is removed.** The two new checks replace it.
- **Install path:** the lifecycle `install` from `rn_forge.tooling.install`,
  with `source=LocalArchive(path, version)` and
  `home=ToolHome("agentkit", <tmp>)`. This is the same API the CLI's `install`
  verb uses.

## Current behaviour

- `src/rn_forge/agentkit/product.py:16-25` defines `check_home`, which returns
  one INFO finding `agentkit.home`. `Tool.checks()` (`:31-33`) returns
  `(check_home,)`.
- `tests/test_product.py:18-22` (`test_the_one_check_reports_the_home`) pins
  that.
- Nothing checks `jq` or the share dir.
- Before the change, tests 1–5 below fail at collection with `ImportError`,
  since `check_jq` and `check_share_dir` do not exist.
- Test 6 exercises existing lifecycle behaviour and is expected to **pass before
  the change**. It pins that behaviour; report in `## Result` whether it did.

## Change

        - Delete `check_home`.

## Tests first

In `tests/test_product.py`, use `ToolHome("agentkit", tmp_path / "home")`. Stub
`jq` with
`monkeypatch.setattr(product_module.shutil, "which", lambda name: ...)`, where
`product_module` is `rn_forge.agentkit.product`. Follow the shape of the
existing file.

1. `test_s4_1_1_missing_jq_is_an_error`: `which` returns `None`. `check_jq`
   returns one finding with code `agentkit.jq-missing`, `Severity.ERROR`, and
   `"jq"` in its message.
1. `test_s4_1_1_jq_present_is_clean`: `which` returns `"/usr/bin/jq"`.
   `check_jq` returns `[]`.
1. `test_s4_1_1_unwritable_share_dir_is_an_error`: create
   `home.root / "share" / "agentkit"`, `chmod` it `0o500`, and restore `0o700`
   in a `finally`. `check_share_dir` returns one finding with code
   `agentkit.share-unwritable`, `Severity.ERROR`, and the share dir's path in
   its message.
1. `test_s4_1_1_absent_share_dir_under_a_writable_home_is_clean`: `home.root`
   exists and is writable, and `share/` does not exist. `check_share_dir`
   returns `[]`.
1. `test_s4_1_1_lifecycle_doctor_reports_both_errors`: `jq` stubbed missing and
   the share dir unwritable (as in 3).
   `rn_forge.tooling.install.doctor(PRODUCT, home=home)` includes both codes,
   each at `Severity.ERROR`.

In the new `tests/test_install.py`:

1. `test_s4_1_1_installs_from_a_local_archive_and_uninstall_keeps_share`:
    - Build `tmp_path / f"agentkit-{PRODUCT.version}.tar.gz"` with `tarfile`. It
      holds this repository's `pyproject.toml`, `README.md` and every file
      under `src/`, skipping `__pycache__`, each under the prefix
      `agentkit-{PRODUCT.version}/`. Locate the repository root from
      `Path(__file__).parents[1]`. The tarball shape follows rn-forge-tooling's
      own `make_archive` test helper.
    - Call
      `install(PRODUCT, source=LocalArchive(archive, PRODUCT.version), home=home)`.
    - Assert that `home.version_dir(PRODUCT.version)` is a directory,
      `home.current` is a symlink, and `home.root / "bin" / "agentkit"` exists.
    - Assert that
      `Process.execute("run", str(home.root / "bin" / "agentkit"), "--version").stdout == f"{PRODUCT.version}\n"`,
      using `Process` from `rn_forge.commons.runtime.subprocess`.
    - Write `share_dir(home) / "marker"`, call `uninstall(PRODUCT, home=home)`,
      then assert the marker still exists and `home.product_dir` does not.
    - This test runs `uv tool install` and needs network access to PyPI for the
      dependencies. Do not skip it or mock it.
