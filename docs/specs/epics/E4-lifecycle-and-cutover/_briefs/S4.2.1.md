# S4.2.1 — Old-install detection and state archive

Brief for
[S4.2.1](../F4.2-machine-cutover.md#s421-old-install-detection-and-state-archive),
at the commit that adds this brief (parent `6e06bb5`).

## Goal

`doctor` reports an old v0 install and an old-format state file, each with the
runbook step that fixes it. A new `agentkit migrate-v0` command renames the old
state file aside, never deleting it, and is a no-op the second time.

## Settled

- **Runbook steps** (S4.2.2 writes `docs/runbooks/cutover-from-v0.md` with these
  numbers): 1 back up, 2 move the old install aside, 3 install, 4
  `agentkit migrate-v0`, 5 `apply --dry-run`, 6 approve adopted files with
  `--force`, 7 trim duplicated body text, 8 remove dead leftovers. The
  findings cite steps 2 and 4.

- **New module** `src/rn_forge/agentkit/cutover.py`, holding:

    - `is_v0_state(path: Path) -> bool`: true when *path* is a file whose text
      parses as a JSON object that has no `schema_version` key. A missing file,
      invalid JSON or a non-object is `False`.
    - `check_v0(home: ToolHome) -> list[Finding]`, a lifecycle check. With
      `install = home.root / "agentkit"` and
      `state = home.root / "share" / "agentkit" / "state.json"`:
        - If `install` holds at least one directory whose name matches
          `^v\d+\.\d+\.\d+$`:
          `Finding("agentkit.v0-install", Severity.WARNING, f"old agentkit install at {install} (v0 layout): move it aside, see docs/runbooks/cutover-from-v0.md step 2")`.
        - If `is_v0_state(state)`:
          `Finding("agentkit.v0-state", Severity.ERROR, f"old-format state file {state}: run agentkit migrate-v0, see docs/runbooks/cutover-from-v0.md step 4")`.
          It is an error because v1 reads that file as empty state and the next
          apply would overwrite it.
        - Install finding first, then state.
    - `migrate_v0(rnf_home: Path) -> Path | None`: with `state` as above and
      `archive = state.with_name("state.v0.json")`:
        - `is_v0_state(state)` and `archive` absent: `state.rename(archive)`, return
          `archive`.
        - `is_v0_state(state)` and `archive` present: raise
          `AppException("{} and {} both exist; move {} aside by hand", state, archive, archive)`.
          Nothing is changed.
        - Otherwise: return `None`, changing nothing.

- **`product.py`**: `Tool.checks` returns
  `(check_share_dir, check_machine, check_v0)`, and its docstring says so.

- **Command** `migrate_v0()` in `src/rn_forge/agentkit/commands.py`, with the
  docstring "Rename a v0 state file to state.v0.json; never deletes it." It
  calls `cutover.migrate_v0(rnf_home())`. Text output:
  `renamed {state} -> {archive}`, or `nothing to migrate`. JSON output
  (`console.mode is OutputMode.JSON`): `{"archived": "<archive path>" | null}`.
  The `AppException` maps to exit 1 through the CLI as other commands' do.

- **Registration**: add to `.rn-forge/kiln/config.toml`, after the `remove`
  entry:

    ```toml
    [[cli.commands]]
    name = "migrate-v0"
    target = "rn_forge.agentkit.commands:migrate_v0"
    ```

    Then run `task kiln:apply`, which regenerates
    `src/rn_forge/agentkit/cli.toml`. Never edit `cli.toml` by hand.

## Current behaviour

- `Tool.checks` (`src/rn_forge/agentkit/product.py:45-47`) returns
  `(check_share_dir, check_machine)`. Neither looks at `$RNF_HOME/agentkit/`
  or the state file's format.
- `StateStore.load` reads an object with no `schema_version` and no `entries` as
  `{}` (commons `fs/state.py:69-111`), so `check_machine` raises nothing for a
  v0 state file.
- `run(app, ["migrate-v0"])` returns `ExitCode.USAGE` (unknown command).
- So each detection test fails because `doctor` lacks the finding, and each
  command test fails with the usage exit code.

   `<rnf>/share/agentkit/state.json`. `doctor` reports `agentkit.v0-state`

   `adapters.render` monkeypatched to one managed artifact, no

   `run(app, ["migrate-v0"])` returns `ExitCode.OK`; `state.json` is gone,

   `ExitCode.OK`, creates nothing.
1. `test_s4_2_1_migrate_refuses_when_archive_exists`: `V0` in `state.json` and a
   different text in `state.v0.json`; returns 1, both files unchanged.
