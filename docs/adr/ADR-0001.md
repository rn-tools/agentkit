# ADR-0001 — agentkit configures agents, and owns no repository prose

**Status:** accepted (2026-11-19) · **Scope:** what agentkit writes, at machine
and repository level

## Decision

agentkit renders coding-agent configuration (Claude Code and Codex) from one
packaged source plus overlays, and writes it to two scopes:

- **Machine scope** (`$HOME`): the agents' user config — instruction files,
  settings keys, output style, guard hooks and skills. This is agentkit's main
  job.
- **Repository scope**: a repository's agent workflow rules, written as one
  fenced block in its `AGENTS.md` ([ADR-0002](ADR-0002.md)), and nothing else
  in v1.

A repository's own rules, docs, `README.md`, Taskfile and CI belong to the
repository and to kiln. agentkit never edits a file body it did not create, and
seeds a file only when it is absent.

agentkit's data lives in `$RNF_HOME/share/agentkit/` (state, backups, the user
overlay, installed hook scripts), outside the `$RNF_HOME/agentkit/` product
directory that `rn-forge-tooling` deletes on `uninstall`.

## Consequences

- Install, upgrade, uninstall, cleanup and release come from the `python-tool`
  archetype and `rn-forge-tooling`; agentkit writes none of that code.
- Removing what agentkit wrote is its own verb, run before `uninstall`, because
  the tooling `uninstall` has no product teardown hook.
- Per-repository native config (`.claude/settings.local.json`, `.codex/**`) is
  out of v1. The one repository that uses it today keeps its files as they
  are.

## Alternatives considered

- **Port the old two-scope tool (machine and repository install).** Its
  repository scope existed because nothing else owned repository files. kiln
  now seeds `AGENTS.md`, `CLAUDE.md`, the Taskfile and the docs tree, so the
  old repository scope would duplicate kiln or fight it.
- **Fold agent configuration into kiln.** kiln is a repository generator, run
  per repository and pinned per repository. Machine configuration is per user,
  with one version installed, so it has a different lifecycle and a different
  failure mode.
- **Machine scope only, no repository block.** Cloud and CI agents (Claude Code
  on the web, Codex cloud) see only the repository, not `$HOME`. Workflow
  rules they must follow have to travel with the repository.

## Background

The previous agentkit (to v0.5.0, retired 2026-11-14) managed both scopes and
seeded `CLAUDE.md` as canonical with `AGENTS.md` as a pointer. Of the 80 files
its last global apply (2026-09-04) recorded, 11 still matched on 2026-11-14: 5
had been edited by hand or by the agents' apps, and 64 skill files had been
deleted, superseded by kiln's docs and Taskfile scaffolding.
