# ADR-0002 — Instruction files: agentkit owns a fenced block, never the body

**Status:** accepted (2026-11-21) · **Scope:** `CLAUDE.md` and `AGENTS.md`, at
machine and repository level

## Decision

Neither agentkit nor kiln owns an instruction file. Every instruction file
agentkit writes to is a **block file**. The body belongs to its owner, the user
or the repository, and agentkit owns one region between
`<!-- BEGIN rn-forge agentkit -->` and `<!-- END rn-forge agentkit -->`.

| File | agentkit's block holds |
| -- | -- |
| `~/.claude/CLAUDE.md` | the shared working rules |
| `~/.codex/AGENTS.md` | the shared working rules, then the output style |
| `<repo>/AGENTS.md` | the repository's agent workflow rules, rendered from its overlay |
| `<repo>/CLAUDE.md` | the `@AGENTS.md` import |

- **Blocks only.** agentkit never seeds a body. When a file is absent, inserting
  the block creates the file with only the block. A repository block that
  renders empty is not written.
- **`doctor` reads only agentkit's blocks.** It reports a missing block, an edit
  inside the block, or malformed markers. It ignores the body and any other
  tool's block.
- **`agentkit review` reads the whole file and only advises.** It suggests
  improvements, never writes, always exits 0, and is no part of a gate.
- The two machine blocks render from **one** source. Claude gets the output
  style through `~/.claude/output-styles/concise.md`. Codex has no
  output-style mechanism, so its block carries the style text.
- A rule that applies to one agent only goes in the body of that agent's file.

## Consequences

- A hand edit to a body is never drift and never a doctor finding. A hand edit
  inside the block is drift, and `apply` blocks on it
  ([ADR-0004](ADR-0004.md)).
- A repository `CLAUDE.md` with a hand-written `@AGENTS.md` line also gains the
  block, so it contains the import twice. `review` suggests removing the body
  line.
- The three body checks `doctor` had (a missing import, a repeated heading, and
  `AGENTS.md` pointing at `CLAUDE.md`) move to `review`.
- The cutover runbook trims duplicated body text using `review`, not `doctor`.

## Alternatives considered

- **agentkit owns the whole of `AGENTS.md` or `CLAUDE.md`.** The owner's rules
  would then live in a file the owner does not own, and every edit would be
  drift. The old tool overwrote `~/.claude/CLAUDE.md`, and the user's
  hand-added `dev-team-orchestration` line would have been lost on the next
  apply.
- **agentkit seeds `CLAUDE.md` as `@AGENTS.md` (the 2026-11-19 rule).** A seed
  writes body text the owner then owns, and kiln seeded the same file, so two
  tools claimed one body. A block keeps the import agentkit's, and lets
  `doctor` notice when it is missing.
- **`doctor` keeps the body checks as warnings.** Doctor would then judge text
  the owner owns, and a clean doctor would require edits that are the owner's
  choice to make.
- **`CLAUDE.md` canonical, with `AGENTS.md` a pointer.** Codex and the other
  readers of `AGENTS.md` cannot follow an import.
- **Machine `CLAUDE.md` importing `~/.codex/AGENTS.md`.** That couples one
  agent's config to another agent's install path, and the two files still
  differ.

## Background

- 2026-11-19: accepted with agentkit seeding a repository `CLAUDE.md` and with
  body checks in `doctor`.
- 2026-11-21: the owner ruled that neither tool owns an instruction file. Tools
  add only blocks, doctor reports drift only inside them, and a separate
  command reviews the rest.
