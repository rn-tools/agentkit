# ADR-0002 — Instruction files: agentkit owns a fenced block, never the body

**Status:** proposed (2026-11-14) · **Scope:** `CLAUDE.md` and `AGENTS.md`, at
machine and repository level

## Decision

Every instruction file agentkit writes to is a **block file**: the body belongs
to its owner (the user, or the repository), and agentkit owns one region between
`<!-- BEGIN rn-forge agentkit -->` and `<!-- END rn-forge agentkit -->`.

| File | Body owner | agentkit's block holds |
| -- | -- | -- |
| `~/.claude/CLAUDE.md` | user | the shared working rules |
| `~/.codex/AGENTS.md` | user | the shared working rules, then the output style |
| `<repo>/AGENTS.md` | repository (seeded by kiln) | the repository's agent workflow rules, rendered from its overlay |
| `<repo>/CLAUDE.md` | repository | nothing: no block |

- The two machine-level blocks render from **one** source. Claude gets the
  output style through `~/.claude/output-styles/concise.md` (a managed file);
  Codex has no output-style mechanism, so its block carries the style text.
- A rule for one agent only goes in that file's body, not in the block.
- A repository block that renders empty is not written. agentkit inserts no
  empty fence.
- In a repository, agentkit never seeds `AGENTS.md`'s body. If `CLAUDE.md` is
  absent it seeds it as the single line `@AGENTS.md`, the shape kiln seeds,
  and it never touches it again. If `AGENTS.md` is absent, inserting the block
  creates the file with only the block.
- `doctor` reports a repository `CLAUDE.md` that does not import `@AGENTS.md`,
  and a body heading that repeats a heading in agentkit's block.

## Consequences

- A hand edit to a body is never drift. A hand edit inside the block is drift,
  and `apply` blocks on it ([ADR-0004](ADR-0004.md)).
- The kiln block and the agentkit block sit side by side in a repository
  `AGENTS.md`, each owned by its own tool's state. Neither tool changes for
  the other.
- Moving rules that are now in a body into a block (for example a worktree rule
  written by hand in a repository's `AGENTS.md`) is an edit in the owner's own
  change, never something agentkit does.
- The first apply on a machine inserts the block into files whose bodies already
  hold the same text. The cutover removes the duplicate body text, and
  `doctor` flags any heading still repeated.

## Alternatives considered

- **agentkit owns the whole of `AGENTS.md` / `CLAUDE.md`.** A repository's own
  rules would then live in a file the repository does not own, and every edit
  would be drift. At machine level the old tool did exactly this. It overwrote
  `~/.claude/CLAUDE.md`, and the user's hand-added rule (the
  `dev-team-orchestration` line) would have been lost on the next apply.
- **Move repository seeding from kiln to agentkit.** A kiln repository then has
  no instruction file until a second tool runs, and kiln's block needs a file
  to live in. Seeding stays with kiln. agentkit seeds only what is absent, so
  in a kiln repository its seed never fires.
- **`CLAUDE.md` canonical, `AGENTS.md` a pointer (the old tool's shape).** Codex
  and the other `AGENTS.md` readers cannot follow an import, so they would see
  only a pointer. Claude Code can import `AGENTS.md`, so the import runs that
  way round.
- **A second agentkit block in a repository `CLAUDE.md`, for Claude-only
  rules.** No Claude-only repository rule exists today, so the block would be
  empty. If one appears it goes in the repository's body.
- **Machine `CLAUDE.md` importing `~/.codex/AGENTS.md`.** That couples one
  agent's config to another's install path, and the two files still differ
  (output style, per-agent rules).
