# ADR-0004 — Built on the commons generation engine; drift blocks

**Status:** proposed (2026-11-14) · **Scope:** how agentkit renders, reconciles
and records what it writes

## Decision

- **Engine.** agentkit renders `Artifact`s and hands them to
  `rn_forge.commons.generation` (`plan`, `apply`, `StateStore`,
  `ManagedBlock`), the engine kiln uses. It keeps no state, backup, staging,
  lock or atomic-write code of its own. Kinds: whole files agentkit owns are
  `managed`, files it writes once are `seeded`, instruction blocks are
  `block`, and settings keys use the kind from [ADR-0003](ADR-0003.md).
- **Drift blocks.** `apply` refuses when a drifted, conflicting or missing
  artifact is in the plan, and names each one. `--force <path>` (repeatable)
  approves overwriting a named path. The engine backs it up first, under
  `$RNF_HOME/share/agentkit/backups/<UTC timestamp>/`.
- **Sources.** Three layers, deep-merged in this order:
    1. the packaged defaults, per agent;
    1. the user overlay, `$RNF_HOME/share/agentkit/config.toml`;
    1. at repository scope, the repository overlay,
       `<repo>/.rn-forge/agentkit/config.toml`.
- **Merge.** Tables merge, and every other value replaces. There is no
  command-line override layer.
- **No write-back into the package.** No command writes into the installed
  package's files.

## Consequences

- Drift is reported the same way in `apply`, `diff` and `doctor`, because all
  three use the engine's one classification.
- A machine whose files predate this state shows each one as a conflict. The
  cutover approves them once with `--force`
  ([F4.2](../specs/epics/E4-lifecycle-and-cutover/F4.2-machine-cutover.md)).
- Capturing a native hand edit back into the user overlay is a later feature,
  parked in [the ideas](../specs/ideas/index.md).

## Influences

- [E1](../specs/epics/E1-apply-engine/index.md).

## Alternatives considered

- **Port the old engine.** Its state, backup and apply loop were rebuilt across
  four epics (E4, E13, E14, E15), and a fifth (E16) was still open for a
  module-global backup timestamp. commons already does this transactionally,
  with rollback, and kiln uses it.
- **Back up and overwrite on drift (the old policy).** A hand edit then
  disappears silently into a backup directory nobody reads. Old agentkit's
  backups were empty because the apply that would have filled them was never
  run again.
- **Keep the `--set KEY=VALUE` layer and an append-merge strategy.** The overlay
  file covers every recorded use of `--set`. Append-merge existed for
  `permissions` lists that the old tool also merged with the user's own
  entries, and under [ADR-0003](ADR-0003.md) the user's entries live outside
  agentkit's keys.
- **`diff --write` and `--promote-defaults` (capture into the package).** The
  old review (feedback item 8) found this writes into an installed package,
  and a test once wrote into the repository's own defaults.
