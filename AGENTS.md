What it is and how to set it up are in [README.md](README.md). The standard,

changing anything structural.

- **Archetype:** `python-tool` · **Docs profile:** `mkdocs` · **CI:** GitHub
  Actions, Sonar on
- **Entrypoint:** `task`. Never invoke `uv`, `pytest`, `ruff`, `pyright`,
  `mkdocs` or `kiln` directly, in a workflow or in a document — the ten root
  verbs are
  `setup validate lint format typecheck test test:coverage build clean version`,
  plus `docs:build docs:serve docs:generate`.

  kiln, not by this repo: edit `.rn-forge/kiln/config.toml` and run
  `task kiln:apply`. An edit in place is drift, and `task lint` fails on it.
- **Docs rules:** [docs/\_structure.md](docs/_structure.md) says what belongs
  where; [docs/index.md](docs/index.md) is the reader's entry point. Run
  `task docs:generate` after adding a page.

  [kiln's architecture baseline](docs/adr/kiln/index.md). A departure from one
  of its records is an ADR of this repo's own, never an edit there.
- **Briefs:** a story ready to build gets a brief under its epic's `_briefs/`,
  deleted when the story closes
  ([docs/specs/\_structure.md](docs/specs/_structure.md#briefs)).
- **kiln is pinned by `[kiln] ref`** in `.rn-forge/kiln/config.toml`, and runs
  in its own environment, outside this repo's lock. CI runs it read-only
  through `task validate` — `kiln doctor` on every run, `kiln doctor --full`
  where the workflow asks — and never runs `task kiln:apply`.
